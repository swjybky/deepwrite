# 长会话渲染验收

2026-09-11，Electron 42.5.0 / Chromium 148，在真实 `AgentConversation` Vue 组件上运行虚构消息夹具。测试不读取真实用户会话或模型配置，不向模型发送请求。结果见 [原始样本](./conversation-view-probe-result.json)。这验证 Renderer 渲染和交互，不代表存储、IPC、模型输入的端到端耗时。

## 已启用的策略

- 每 16 条消息形成稳定 DOM 分组；达到 512 条消息才启用 `content-visibility: auto`。阈值上下切换不重新挂载消息，避免打断编辑和原生选区。
- 活动、编辑、已选择及聚焦消息所在组保持正常渲染。折叠详情只在展开后挂载，展开状态在列表作用域保存。
- 浏览器保留所有历史正文节点，跳过屏幕外布局与绘制；组高度使用 `auto` 已测量值与随字号缩放的 `lh` 估值。
- 已启用延迟布局的长历史使用即时导航，避免浏览器平滑滚动沿旧几何位置停止。普通短会话仍保留平滑导航。
- 字号或容器宽度变化时按消息 ID 和像素偏移校正位置，最多等待 3 帧布局稳定。用户滚轮、指针或键盘操作立即取消校正。

## 实测结果

每个规模按关闭、开启、关闭、开启顺序运行，每个样本流式更新 40 帧。小量样本仅用于发现明显回归，不能视作精确性能保证；首次模块冷启动约 33 ms，与开启策略无关。

- 10 轮 / 20 消息：两模式均不启用延迟布局，579 DOM 节点；暖挂载 9.9–10.1 ms，输入 p95 0.6–1.4 ms。
- 100 轮 / 200 消息：两模式均不启用延迟布局，5,000 DOM 节点；挂载 46–52 ms，流式 p95 1.5–1.8 ms。
- 1,000 轮 / 2,000 消息：挂载从 420–451 ms 降至 281–285 ms；流式 p95 从 5.1–7.2 ms 到 5.0–5.4 ms；输入 p95 从 1.1–1.4 ms 到 0.9 ms；帧间隔 p95 17.6–18.6 ms 到 17.6 ms。
- 2,000 消息两模式都保留 49,212 DOM 节点。开启时 124 个静态组可延迟渲染，最后活动组保持正常渲染。
- 上滚锁定后继续生成，滚动偏移为 0；历史导航目标距视口顶端 21.75 px（预期 22 px）。
- 原生 Cmd+A 与跨全部历史的 Range 选区，开启/关闭的文本长度和 SHA-256 完全相同。1,000 轮全文 Range 长度 364,996，Cmd+A 长度 366,033。
- 字号 10–24 px 的各次切换，锚点误差不超过 0.375 px；700、950、1,100 px 容器宽度变化误差为 0。
- 原生 summary 焦点、编辑中、已选择、活动组豁免，以及选区插入正文引用均通过。浅色、深色与自定义强调色读取实际主题变量，未出现横向溢出。

## 可重复执行

在仓库根目录执行：

```sh
node apps/desktop/scripts/conversation-vue-probe.mjs /tmp/conversation-vue-result.json
node apps/desktop/scripts/conversation-vue-probe.mjs /tmp/conversation-vue-interactions.json --interactions-only
```

第二个命令同时保存 PNG。夹具用独立临时 Electron 配置目录、随机本地服务端口，不读取客户端用户数据，不改 `out`；禁用 HMR，避免同时构建或编辑导致夹具重载。脚本会对滚动、导航、原生选区全文一致性、编辑/焦点/活动豁免、选区插入与锚点误差执行失败断言。性能原始值保留供对比，不根据单轮微小噪声判定通过。

另有 `conversation-view-probe.mjs` 纯 DOM 对照夹具，用于隔离浏览器布局行为；生产结果以真实 Vue 夹具为准。

## 仍未解决的边界

已移除试验阶段未接入生产的虚拟列表组件、可变高度索引与范围窗口实现，只保留生产渲染所依赖的选区/编辑/焦点保护及滚动锚点。未挂载文本不能参与原生跨范围选择、Cmd+A 或原生查找；仅固定已有选区不构成等价替代，因此生产继续使用完整 DOM 与 `content-visibility`。

当前优化不限制完整历史正文 DOM、文本对象或进程总内存。存储分页、冷详情缓存与 Renderer 数据按需加载仍需独立整合，不能将本结果表述为 DOM/内存已有固定上限。跨消息全文原生选择必须在后续任何卸载方案中继续保留。

## 历史管理与保存状态验收

```sh
node apps/desktop/scripts/conversation-vue-probe.mjs /tmp/conversation-management.json --management-only
```

此夹具使用真实 `ConversationHistoryMenu`、`ConversationSaveStatus`、`useAgentConversation` 和 Store 保存队列；存储 I/O 采用可控制确认时机的虚构后端，不替代 Core/SQLite 事务测试。[结果样本](./conversation-management-probe-result.json) 验证了：

- 删除按钮先显示确认；确认后重复点击不重复提交，持久化确认前保持原历史。
- 确认成功后移入已删除；恢复调用成功后重回全部历史。
- 待处理提案等后端拒绝通过浮层说明原因，原历史与确认框保持。
- 保存队列实际驱动“等待保存 → 正在保存 → 保存失败 → 重试仍保存失败 → 已保存”；错误保持到确认，详情按钮显示浮层原因，工具栏槽宽始终为 107 px（默认字号）。
- 保存失败处和历史菜单共用导出入口，真实点击后按需加载编码模块；测试接收端读回当前消息与尚未保存的草稿，导出不清除保存错误。
- 浅色/深色、自定义强调色与 10/14/24 px 字号下，菜单与删除弹窗没有横向裁切；截图保存在命令指定 JSON 的同名 PNG。

聊天助手的历史切换等待 `openConversation` 完整加载后才聚焦输入；读取失败显示浮层反馈，沿用原会话。旧控制器的同步选择入口保留兼容。

## 当前对话 JSON 导出

用户点击导出后，先捕获当前控制器的消息、草稿及运行设置，再显示保存位置选择。快照包含当前可见数据中的提案、撤回信息、原始参数和未确认保存内容，不要求数据库先保存成功。格式为 `deepwrite.conversation-recovery` 第 1 版，并明确标记 `scope: current-controller-session`、`includesUnconfirmedChanges: true`、`unknownDatabaseFieldsIncluded: false`。它不是全库备份，也没有一键导入功能。

编码按小片段处理文本，每次发送最多 1 MiB UTF-8；单个字段超过 64 MiB 的测试也不调用整字段或整记录 `JSON.stringify`。Main 只授权用户在原生对话框选定的位置，Renderer 仅持有 UUID token；Core 分块写入同目录临时文件，确认同步后原子重命名。nonce、序号及数据摘要允许确认丢失后的同内容重试。写入失败的临时文件不会继续复用；重命名失败可重试；取消、Renderer 销毁、超时及正常退出清理临时文件。磁盘写入失败后可以重新选择保存位置。
