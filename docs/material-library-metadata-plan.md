# 素材库优化方案：可选元信息与智能体主动发现

状态：已完成第一、第二阶段实现；实际落点与验证记录见第 10 节。  
日期：2026-09-07。

## 1. 方案结论

在素材条目的 Markdown 顶部支持可选的 `name`、`description` 配置。智能体每轮先收到当前可读素材的名称、用途说明和稳定 ID，需要参考时再读取对应条目的正文。

采用类似技能的“先告知有哪些、何时适用，再按需读取”交互，但素材的元信息始终是建议配置：没有配置、只配置一项、字段为空或配置格式错误，都不能让原本可用的素材消失、无法保存或无法读取。

原方案分两阶段设计，本次已一并实现：

1. **核心阶段：可选元信息、兼容回退、主动注入目录、完善现有读取工具和编辑建议。** 同时保留原附件快照的兼容读取。
2. **按需读取阶段：元信息索引与受控正文读取。** 写作发送流程不再让 Renderer 批量装载素材正文；Core 首次建立索引仍需读取，后续利用版本缓存。

第 3–9 节保留分阶段设计和验收要求；当前默认路径采用第二阶段，附件快照仅用于兼容与显式回退。

## 2. 改动前的实现与设计起点

本节记录方案制定时的代码情况，实际完成状态见第 10 节。

- 素材库和技能库共用 Folder Catalog。每个库保留 `deepwrite.json`，每条素材保存在 `entries/<条目id>.md`；库介绍是清单中的 `overview`。目录结构见 [技能库 / 素材库结构](./skill-and-material-library-structure.md)。
- [MaterialEntrySchema](../packages/contracts/src/catalog.ts) 当前包含 `id`、`stageId`、`title`、`body` 和时间字段，没有 `name`、`description`。轻量 Catalog 索引中的条目 `body` 固定为空，不能把这个空值误当成真正的素材正文。
- [libraryAttachments.ts](../apps/desktop/src/renderer/src/utils/libraryAttachments.ts) 从已关联的库构建附件，使用 `库名 · 条目名` 作为标题，使用 `material:<libraryId>:<entryId>` 作为基础附件 ID。当前会过滤不匹配分类和空内容，并按现有容量上限裁剪。
- [useShortConversationCoordinator.ts](../apps/desktop/src/renderer/src/composables/useShortConversationCoordinator.ts) 在发送前先确保上下文文档装载，再构建附件；这与“模型通过工具才看到正文”是两个不同层面的行为。
- [prompts.ts](../packages/pi-runtime-adapter/src/prompts.ts) 已向短篇、剧本和长篇写作智能体注入可读素材的标题、分类、ID，正文通过 `query_linked_material_entries` 读取。因此此次主要增强目录信息和发现能力，无需另建一套素材工具。
- [短篇 / 剧本素材工具](../packages/pi-runtime-adapter/src/short-agent-tools/catalog-tools.ts) 已支持 `list`、`search`、`read`，读取可用完整标题、稳定 ID 或唯一短名；[长篇素材工具](../packages/pi-runtime-adapter/src/long-agent-tools/catalog-tools.ts) 当前读取只匹配完整标题，需要同步补齐。
- [parseSkillMarkdown](../packages/contracts/src/skill-markdown.ts) 将缺少 `name`、`description` 或正文判定为无效；编辑器会展示技能格式错误。素材必须使用独立的宽容解析规则，不能直接套用该结果作为准入条件。

优化覆盖短篇、剧本和长篇中的关联素材使用。素材库自身的编辑智能体仍沿用现有资料库工作区工具；增加元信息并不意味着把素材注册成技能，或自动关联所有素材库。

## 3. Markdown 格式与字段语义

配置加在每条素材的 `.md` 文件上，不要求改名为 `SKILL.md`，也不新增目录层级：

```markdown
---
name: 身份错位引发的关系反转
description: 适合都市情感或悬疑故事，在人物关系设计、身份揭露和冲突升级时参考。
---

# 身份错位引发的关系反转

人物最初基于错误身份建立关系，关键事件迫使双方重新判断彼此的立场。

## 可替换变量

- 身份误判的来源。
- 揭露真相的时机。
- 真相对人物利益和情感的影响。
```

- `name`：供智能体识别的素材名称，允许中文、空格和重名。建议简短、具体。
- `description`：说明素材内容及适用场景，例如题材、创作阶段、情绪或冲突类型。建议一至两句，避免复制整篇正文。
- 两个字段都可省略，互不依赖。正式字段名使用 `description`。
- 清单的 `title` 继续控制条目标题和左侧树名称；`name` 作为智能体目录中的名称，不自动重命名条目、文件或库。
- 条目的身份、分类、阶段和关联关系继续由现有 ID、`stageId` 和清单决定；元信息不能改变读取权限。
- `overview` 保持库级介绍，不作为每条素材的默认 `description`，避免同库条目出现完全相同的用途说明。

首版提供明确、有限的 frontmatter 语法：文件开头的 `---` 块，字段值采用单行文本，可带成对单引号或双引号；兼容 UTF-8 BOM 和 CRLF。暂不承诺完整 YAML 语法，多行块、对象、数组等不支持的写法产生可忽略的建议并回退，不影响原文读取。

## 4. 旧素材兼容规则

### 4.1 名称和描述分别回退

每个可用素材都生成有效目录信息，不使用“只有配置完整才进入目录”的过滤条件。

名称按以下顺序取得：

1. 可解析且非空的 `name`。
2. 原有条目 `title`。
3. 异常缺少标题时，使用条目 ID 作为最后回退。

描述按以下顺序取得：

1. 可解析且非空的 `description`。
2. 素材正文首个有内容的段落摘要；跳过标题、分隔线和可明确识别的元信息，折叠空白，保留可读文字。
3. 无法提取摘要时，显示“暂无说明，可读取原文了解内容”。

回退摘要采用确定性的本地文本提取，不调用模型、不增加费用、不写回 Markdown。目录中将其标为“正文摘录”，避免智能体把自动摘录误认为用户填写的使用说明。

建议初始展示上限为名称 80 字符、描述或摘录 160 字符；这是目录展示预算，不是保存准入条件。超长内容保留在原文件中，展示时省略并提供稳定 ID，不能因为长度超限丢掉整个素材。

### 4.2 各种文件都能继续使用

- **完全没有 frontmatter**：保留原文，以条目标题和正文摘录进入目录，原有搜索、读取和保存继续生效。
- **只有 `name`**：使用配置名称，描述从正文回退。
- **只有 `description`**：使用原条目标题和配置描述。
- **字段为空或只包含空白**：仅该字段回退，另一有效字段继续生效。
- **有其他 frontmatter 字段**：保留未知字段；只读取本方案关心的两个字段，不删除用户已有配置。
- **缺少结束分隔符、存在歧义或格式不支持**：无法安全识别时保留完整原文，采用旧素材回退；不得按猜测删除文件开头的一段内容。
- **某字段重复定义**：该字段回退并给出建议，避免静默采用不确定的值；另一个明确有效的字段可以继续使用。
- **正文以 Markdown 分隔线开头**：仅有 `---` 不足以判定为素材配置，不应误剥离旧正文。
- **多个素材使用同一 `name`**：全部保留在目录中，使用库名、原标题和稳定 ID 区分。

解析结果建议分为 `configured`、`partial`、`legacy`、`malformed`，仅用于展示和诊断，不提供决定素材可用性的 `valid: false` 开关。回退来源分别记录为 `nameSource`、`descriptionSource`，从而正确处理只填一项的情况。

兼容承诺针对原本可用的素材。原有的权限限制、文件不存在、真实磁盘读取失败和容量限制仍按原逻辑处理；元信息缺失不应被归入“无法读取的素材库”，也不应令附件构建的 `complete` 变为 `false`。

### 4.3 原文件是唯一真相源

第一阶段仍将 Markdown 原文放入附件 `content`，元信息只是派生信息。搜索保留对原文的匹配，读取返回完整原文，包括原本存在的 frontmatter，避免改变旧工具的内容语义。

升级不批量迁移，不改写旧文件，不修改 `deepwrite.json` 的结构版本，不重建 ID、分类、分组或书籍关联。导入、导出、复制和备份继续保存原始 Markdown；移除元信息后，条目自然回到旧素材回退模式。

## 5. 智能体如何主动发现和读取

### 5.1 每轮告知可读目录

发送时先沿用现有关联和权限规则，得到本轮可用素材集合，再为这一集合生成目录。短篇 / 剧本保留阶段读取限制，长篇保留书籍绑定、阶段启用范围和智能体读取范围。

示例固定上下文：

```text
当前可按需读取的关联素材：

- 名称：身份错位引发的关系反转
  来源：情感剧情素材 · 身份错位
  分类：plot
  说明：适合人物关系设计、身份揭露和冲突升级。
  id：material:library-a:entry-a

- 名称：雨夜重逢
  来源：场景素材 · 雨夜重逢
  分类：draft
  正文摘录：多年未见的人在末班车站相遇，双方都没有先提起过去……
  id：material:library-b:entry-b

先根据名称、说明或正文摘录判断相关性。
用户点名素材，或当前任务与某条素材明显相关时，读取该条素材原文后再参考。
目录信息用于发现素材，不能代替正文，也不代表这些内容已经成为当前作品设定。
需要查找未确定的素材时，使用 query_linked_material_entries 的 search 或 list。
```

配置完整和未配置的素材混合列出，沿用原有顺序，不默认将旧素材降权或排到末尾。目录仅包含本轮实际可读的条目，不能展示一个工具无法读取的“可用 ID”。

不要求智能体每轮先 `list` 一遍或把全部素材读完。它应直接根据目录选择相关条目；仅凭目录不能声称已经读过正文。

### 5.2 扩展现有工具

保留 `query_linked_material_entries` 和 `list`、`search`、`read` 三种模式，不新增平行的 `load_material` 工具。

- `list`：返回名称、描述或摘录、原标题、分类和稳定 ID，使用与固定上下文一致的派生规则。
- `search`：在原有标题和全文搜索基础上，增加 `name`、`description` 匹配；无配置的素材仍然可以通过正文命中。返回简短命中片段，不批量返回全文。
- `read`：建议增加可选 `entry_id`，使用目录提供的稳定附件 ID 精确读取。保留原有 `entry_name` 和 `query` 回退调用方式。

有 `entry_id` 时，以 ID 精确定位；没有时，先保留现有完整标题、ID、唯一条目短名的匹配优先级，再补充 `name` 匹配，避免新增别名覆盖旧调用含义。任一层出现多候选均返回可读候选和 ID，由智能体改用 ID，不静默读取第一条。

示例：

```json
{
  "mode": "read",
  "entry_id": "material:library-a:entry-a"
}
```

长篇同步采用相同解析规则。公共的素材匹配和目录格式逻辑放在 runtime adapter 的独立素材模块中，各工作区仍负责自己的权限过滤，避免两套实现继续分叉。

元信息属于用户资料。目录序列化应正确处理换行和分隔字符；其中的文本不改变系统提示词、工具权限或自动执行行为。

### 5.3 容量和截断

[运行时契约](../packages/contracts/src/session/runtime.ts) 当前每类附件最多 64 条、每条内容最多 100,000 字符。第一阶段保留这两项限制，不因为新增元信息额外减少旧素材的附件名额。

目录超出展示预算时，先缩短描述，再省略部分详情，同时明确说明可用条目总数和 `list` 入口。只允许省略提示词展示，不得同步从工具可读集合删除条目。

现有超过 64 条的附件遗漏，以及正文超长截断，继续保留明确诊断；不能把已有容量限制包装成“所有素材已经全部可用”。解除附件数量与正文传输的耦合放在第二阶段处理。

## 6. 用户界面：提供建议，不设门槛

素材编辑器在现有工具栏预留“素材说明”入口，打开后展示有效名称、描述及其来源。未配置时使用稳定辅助文案：

> 建议添加名称和使用说明，帮助智能体更准确地选择素材。不填写也可以正常使用。

具体交互：

- 新建素材提供“添加名称与说明”操作，使用条目标题预填 `name`，`description` 可为空。用户可跳过，不增加创建或保存的必填项。
- 旧素材只展示可忽略的建议，不在每次打开、保存或发送消息时重复弹警告，不要求先补齐才能关联。
- 单击添加配置后先修改编辑草稿，用户正常保存时才落盘；不在浏览文件时自动写入。
- 已有 frontmatter 时只更新明确识别的字段，保留未知字段和正文。遇到无法安全修改的结构，保留原文并提示用户在编辑器调整，不强行重建整个头部。
- 临时操作结果和解析提示使用自动消失的 toast / message，不在正文和按钮之间插入错误块，不使用模态确认要求补齐元信息。
- 使用现有主题变量、字号和中性主按钮；如需选择框则复用 `PopupSelect`，同时验证浅色、深色、自定义强调色和较大 UI 字号。

学习仿写生成素材、资料库智能体创建素材等入口可默认建议产出同样的头部，格式未遵循时仍接受原有内容。生成内容继续先进入预览或 proposal，用户接受后由 Core 落盘。第一阶段不提供自动批量改写旧素材的操作。

## 7. 第一阶段的实现落点

### 7.1 Contracts：独立的宽容解析和兼容字段

新增建议模块 `packages/contracts/src/material-markdown.ts`，提供无 IO 的素材元信息解析、来源标记和回退规则。它与技能解析器各自保留领域规则，不为实现素材兼容而放松技能格式要求。

在 `AttachedMaterialSnapshotSchema` 中增量添加可选的名称、描述及来源字段。旧的 `{ id, title, content, source, kind }` 附件仍然通过 Zod 校验；缺少派生字段的历史运行数据，由运行时从 `content` 和 `title` 补齐。不要把名称和描述加成旧清单或正文的必填字段。

解析原始文本后再进行目录长度裁剪，不能直接把不受控原始字段交给有长度上限的 Schema，导致整轮会话因单条配置过长失败。元信息建议通过独立结果返回，不能混入会阻断发送的附件错误集合。

Renderer 需要使用的运行时导出同步加入 `packages/contracts/src/renderer.ts`，Renderer 从 `@deepwrite/contracts/renderer` 使用。

### 7.2 Renderer：附件构建和编辑建议

- 在附件构建时统一生成素材元信息；提取基于已装载正文，不能基于 Catalog 轻索引中的空 `body`。
- 编辑器使用相同解析规则展示草稿建议，保存和重发后以相应最新内容重新计算，不能沿用过期描述。
- 短篇、剧本、长篇共用派生逻辑，同时保持各自的关联范围和读取限制。
- 元信息编辑通过原有保存路径提交，并沿用 `baseRevision`、`baseProjectRevision` 冲突校验；普通补充说明不能绕过冲突检查强制覆盖较新原文。

`libraryAttachments.ts`、`RightEditorPane.vue` 和相关 coordinator 已较大。实施时将触及的素材派生、编辑提示或附件编排职责拆到独立模块 / composable / 子组件，按仓库体量规范处理，不继续往大文件堆积逻辑。

### 7.3 Runtime adapter：目录与读取一致

从 `prompts.ts` 抽出素材目录构建职责，供短篇、剧本和长篇统一使用。素材工具调用相同的名称解析、摘要和格式函数，保证提示词中展示的 ID 可被工具读取，目录和搜索不会使用不同的回退名称。

保留既有工具集合和主流程。只有具备素材查询工具的写作上下文采用该目录方案，不能将没有对应工具的其他上下文改成“只给目录”而失去正文访问能力。

### 7.4 Core 与生成入口：保持现有写入协议

第一阶段不新增 Agent 直接读写本地文件的通道。继续通过现有 `catalog.saveLibraryEntry`、创建和导入路径保存 Markdown 原文，不因缺少配置拒绝素材。

更新生成素材的提示说明时，同步覆盖学习仿写预览和资料库智能体创建场景，并维持现有预览 / proposal / 用户接受流程。该调整是输出质量建议，不是新的工具输入必填校验。

## 8. 第二阶段：真正减少统一读取

若继续优化发送前的素材加载成本，目标流程为：

```text
Core 维护可重建的条目元信息索引
→ Main 确认本轮书籍关联、阶段和智能体读取范围
→ 会话携带授权范围内的元信息目录
→ 智能体选择条目并调用现有素材工具
→ Agent 经 Main 授权的内部命令桥请求 Core
→ Core 按 ID 校验并读取所选条目
→ 返回该条正文与内容版本
```

这一阶段必须成套实施，不能仅将附件 `content` 清空后仍让现有工具从内存附件读取。

1. **索引与缓存。** 在现有 Catalog 索引投影中扩展可选元信息。Core 以条目 ID 和内容版本 / stamp 缓存结果；缓存可删除重建，不成为新的正文或配置真相源。旧素材同样生成标题和摘录索引。首次建索引仍有读取成本，后续按变化更新，明确这一性能边界。
2. **读命令与权限。** 先在 contracts 定义 Catalog 素材查询 / 读取的 Envelope 和 Schema，再扩展现有 Main 内部命令桥白名单及 Core handler。现有桥的长篇查询授权不等于素材查询已经获得授权。Main 按活动 run、书籍绑定、阶段和分类校验，不能只相信 Renderer 传来的任意 ID 或路径。
3. **运行时工具。** `list` / `search` / `read` 改调受控查询接口，保持第一阶段名称、ID 和回退规则。正文关键词搜索由 Core 在授权范围内执行；只有 `read` 将选定正文返回模型，不将全部原文重新装入会话附件。
4. **容量扩展。** 区分“提示词已展示条目”与“本轮授权可查询条目”。目录和搜索增加有界分页，模型可继续获取未展示条目；同步更新契约，不能仅提高数组上限而继续传输所有正文。
5. **一致性。** 目录携带内容版本；读取时若版本变化，返回最新正文及新版本并明确告知。删除或撤销关联后返回不可读，下一轮刷新目录；不得把旧缓存当成仍获授权的当前内容。
6. **回退。** 在新读取链路不可用时，可显式回退到仍可构建的原附件快照并提示实际容量限制，不能静默返回空正文。功能开关关闭时仍可按第一阶段读取相同的 Markdown 文件。

完成后才可宣称发送前无需为关联素材统一装载全部正文。这一阶段不引入向量数据库、自动语义检索服务或新的平行素材存储。

## 9. 验收与回归检查

第一阶段以以下结果作为验收条件：

1. **旧库零修改可用。** 用现有无 frontmatter 素材库直接升级，文件内容、ID、关联关系和可读条目不因元信息要求变化；仍可打开、编辑、保存、搜索和读取。
2. **宽容解析。** 覆盖完整配置、缺任一字段、空值、BOM、CRLF、未知字段、重复字段、未闭合头部、不支持的语法和正文分隔线。所有建议都不阻断保存、发送或读取。
3. **主动发现。** 短篇、剧本和长篇首轮及后续轮次都能看到有配置素材的名称与说明，以及旧素材的标题与正文摘录。仅注入目录，不额外注入整篇正文。
4. **名称兼容。** 原完整标题、原 ID、短篇 / 剧本原有唯一短名调用继续有效；新增名称可查询；重名时返回候选并通过 ID 精确读取；长篇同步覆盖。
5. **正文保真。** 搜索仍能命中旧素材正文；读取结果保留原文；添加建议、解析失败和版本升级不会静默改写文件。
6. **权限一致。** 未关联、阶段禁用或当前智能体不可读的素材不会出现在目录、搜索结果或正文读取中，不能通过指定 ID 绕过。
7. **容量不倒退。** 配置缺失和超长不会额外占用或减少附件名额；已有容量和正文截断诊断仍保留；提示词省略详情后，条目仍可通过工具查询。
8. **界面与并发。** 建议可忽略、不触发布局跳动、不重复骚扰；新建和旧素材均无需填齐才能保存；原文并发修改仍触发既有版本冲突处理。
9. **跨入口一致。** 手写、导入、复制、学习仿写生成和资料库智能体生成的素材均适用相同规则；新旧运行时附件均可被契约接受。

实施时重点增加解析器、附件构建、提示词目录、短篇 / 剧本 / 长篇工具和保存兼容性的行为测试。测试数据只使用虚构素材及无效占位值。提交实现前，从仓库根目录运行 `pnpm verify`。

第二阶段另行验证：目录热缓存时发送前不批量读取正文、只读选中条目、全文搜索不向模型转储全库、超容量目录可继续查询、外部编辑后缓存失效、撤销关联即时拒绝读取，以及关闭新链路后旧素材仍可使用。


## 10. 实施结果（2026-09-07）

### 10.1 可选配置与编辑体验

- [material-markdown.ts](../packages/contracts/src/material-markdown.ts) 独立解析素材元信息，名称和描述分别回退。缺失、空值、重复、超长和无法识别的头部都不会使素材失效，技能的必填规则保持独立。
- [MaterialMetadataEditor.vue](../apps/desktop/src/renderer/src/components/MaterialMetadataEditor.vue) 在素材编辑器提供“素材说明”浮层，显示当前名称、说明及其来源。两项均可不填；操作只修改编辑草稿，继续使用原有保存与版本冲突处理。
- [material-markdown-edit.ts](../packages/contracts/src/material-markdown-edit.ts) 保留正文、未知字段、BOM 和换行方式；无法安全修改时只给浮层提示，仍可直接编辑与保存原文。没有自动迁移或批量补齐旧素材。
- 素材库智能体和学习仿写的素材拆解提示均增加可选配置建议，继续使用原有预览、提案和接受流程。

技能编辑器也已加入“技能说明”入口，和素材说明共用 [LibraryMetadataPopover.vue](../apps/desktop/src/renderer/src/components/LibraryMetadataPopover.vue) 的浮层、主题、焦点与草稿交互；两个说明编辑器按需加载。[SkillMetadataEditor.vue](../apps/desktop/src/renderer/src/components/SkillMetadataEditor.vue) 按原有技能格式读取和写入 `name`、`description`，两项仍为技能必填配置，正文仍是技能可用条件；未填齐、无法安全修改头部时使用临时浮层提示。补充说明不会自动保存、重命名条目或修改关联，取消与只读状态均不会改写草稿。技能说明的填写、空值提示、已有配置回填、取消、只读、深浅主题和 24px 字号 / 640×480 窗口已通过组件交互验证。

### 10.2 默认按需读取路径

1. Renderer 写作发送流程只装载仍需作为附件使用的技能与作品上下文，素材正文不再进入该批量装载步骤。
2. [material-run-context.ts](../apps/desktop/src/main/material-run-context.ts) 由 Main 结合已解析的智能体配置和本轮创作阶段建立读取范围，向 Core 获取目录，替换 Renderer 提供的素材目录。
3. [material-query-service.ts](../apps/desktop/src/utilities/material-query-service.ts) 在 Core 生成元信息目录，按内容 stamp 与条目标题缓存。每次查询重新读取当前书籍关联；长篇还检查库的阶段启用范围。
4. [material-query.ts](../packages/contracts/src/material-query.ts) 定义内部 `catalog.queryMaterials` 命令及 Zod 输入输出。Agent 仅通过已有 Main 内部桥访问 Core，Main 校验活动 run、session、父请求、书籍、阶段和分类范围；该命令不开放为 Preload API。
5. [material-query-runtime.ts](../packages/pi-runtime-adapter/src/material-query-runtime.ts) 将短篇、剧本、长篇的现有 `query_linked_material_entries` 接到上述命令。`list` 和 `search` 分页返回目录与简短命中片段，`read` 返回选定素材的完整原文与版本。首轮和后续轮次均刷新目录提示。

原完整标题、稳定 ID、唯一短名继续可用，新增配置名称匹配；重名返回候选，不直接选第一条。旧素材仍能通过全文检索命中。读取过程中再次检查关联，删除或解绑后的缓存不能继续提供原文。关联库缺失、分类改变或单条读取失败保留诊断，不因某条素材配置缺失报错。

### 10.3 容量与性能边界

- 首轮目录最多携带 64 条；工具每页 32 条，可用 `cursor` 继续查询。已用 70 条素材测试跨页读取，默认路径不再受旧附件总数 64 条限制。
- 提示词目录详情预算为 12,000 字符，先缩短说明，再省略超出部分，并保留总数和工具入口；工具读取范围不随提示词截断。
- Core 缓存仅保留元信息、版本和少量索引标记，不缓存整篇正文；最多保留 16,384 条，可随进程重启或容量淘汰而重建，不改变 Catalog 清单格式。
- 冷缓存和变化条目仍需读盘提取元信息。热缓存且 stamp 未变时不再批量打开正文。全文搜索仍由 Core 扫描范围内原文，所以不承诺首次发送或搜索没有磁盘成本。
- `DEEPWRITE_MATERIAL_SNAPSHOT_MODE=1` 可在启动 Main 时显式切换到附件快照：Main 通过 Core 构建原文附件，保留 64 条和每条 100,000 字符的旧容量约束及截断提示。它用于关闭运行时按需读取，仍依赖 Core 可读；Core 查询失败会明确报错，不会自动伪造空正文或成功结果。
