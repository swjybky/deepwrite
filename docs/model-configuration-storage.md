# 模型配置的原子存储

模型配置由 Main 的 `ModelConfigStore` 管理。所有用户修改、官方令牌修改、启用状态修改和远程目录刷新，共用串行的状态更新与持久化入口。

## 磁盘格式

`config/models.json` 的 V3 格式同时包含模型元数据与 `encryptedApiKeys`。密钥仍由 Electron `safeStorage` 加密；Renderer 只收到经过 Schema 校验的公开设置及 `hasApiKey` 标记。文件以 `0600` 权限创建。

保存时在同一目录独占创建临时文件，写入完整状态、同步文件并关闭，再通过一次 `rename` 提交，最后在平台支持时同步目录。地址与密钥不再分两次提交。

- 替换前失败：保留完整旧配置。
- 替换完成：新配置整体生效。
- 替换后的目录同步或确认失败：调用可能返回失败，但重新加载只读取完整新配置，不单独回滚密钥或元数据。
- 上次进程遗留的临时文件不会被当成有效配置。

## 旧格式迁移

读取 V1/V2 的 `models.json` 时，同时读取旧 `model-secrets.json`。下一次正常持久化把两者合为 V3；只有新文件提交并完成目录同步后，才尝试清理旧密钥文件。

迁移在提交前失败时，原来的两个文件保持不变。旧密钥文件清理失败不改变已完成的提交；V3 读取器只认 V3 内的密钥，即使旧密钥文件仍存在，也不会回退读取它。当前文件语法损坏、版本不支持或 V3 缺少有效密钥映射时，读取报错并保留文件。

此迁移不承诺旧版客户端可以读取 V3。需要回退客户端版本时，应恢复与该版本配套的配置备份；不能只替换元数据或密钥其中一个文件。

## 代码责任

- `model-config-store.ts`：公共方法、串行更新与目录刷新编排。
- `model-config-persistence.ts`：磁盘格式、迁移与单文件原子提交。
- `model-config-mutations.ts`：用户编辑与令牌/启用状态变更。
- `model-config-state.ts`：托管模型同步与公开设置投影。
- `model-config-runtime.ts`：运行时配置解析与 Main 内密钥解密。

回归测试覆盖部分写入、文件同步失败、替换失败、替换后确认失败、旧格式迁移、旧文件残留、清除密钥、删除模型及失败后的后续保存。测试仅使用保留测试域名与无效占位密钥。
