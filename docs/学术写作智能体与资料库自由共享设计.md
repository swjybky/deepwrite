# 学术写作智能体与资料库自由共享设计

> 状态：设计已确认（2026-11-17），待分期实施。
>
> 范围：创作空间新增 `academic`（学术写作）作品类型、学术主创智能体、独立管理的学术智能体团队（含默认团队）、资料库（素材库与技能库）自由标签与分组松绑及跨文体绑定，以及第一版 `.md` / `.docx` 导出。

---

## 1. 目标与设计原则

1. **创作空间一等公民**：学术写作与 `short`（短篇）、`script`（剧本）、`long`（长篇）并列，走 `session.prompt` 与 `pi-runtime-adapter/src/kernel/` 共享内核，不放入“更多功能”扩展智能体。
2. **先给思路、拆解框架、分步写作**：通过「研究底座 → 可配置论证阶段 → 分节/分章正文（含写作指引与节末状态）」三层结构，阻止模型从一句话直接跳到几千字空洞水文。
3. **防幻觉死线**：严禁编造未在作品「文献与证据卡」或已绑定素材库中核实的文献题录、DOI 与实验数据；缺失处强制输出 `[待补引用: ...]` / `[待补数据: ...]` 显式占位。
4. **一套结构通吃小论文与大论文**：原子写作单元固定为“节（Section）”；正文目录自适应单层“节”（期刊/会议单篇、申报书、技术报告）与两级“章 → 节”（5～10 万字硕博学位论文），全文内容经 Core 只读桥按需读取与检索。
5. **资料库彻底去死板约束**：分类退化为纯展示与筛选标签（精简预设 + 支持自定义），分组取消分类槽位限制改为自由组合，所有作品类型均可跨文体自由绑定任意素材库与技能库。
6. **作品结构纯粹，衍生归于导出**：作品内部不塞“投稿/发布套件”分区；第一版打磨核心写作与 `.md` / `.docx` 导出，后续再在导出入口扩展 Cover Letter、Rebuttal、解读推文等衍生件。

## 2. 学术作品结构与存储模型

### 2.1 存储与清单（`packages/contracts/src/catalog/` & `folder-catalog-store`）

学术作品采用独立作品文件夹存储（`deepwrite.json` + UTF-8 Markdown 文件），由 Core Utility 的 `folder-catalog-store.ts` 原子写入，直接复用现有的版本管理（`document-versions/`）、正文插图（`book-images/`）、Core 按需只读桥（`readSource: "core"`，单作品上限 `CATALOG_PROJECT_MAX_CONTENT_ITEMS = 4_096`）与外部控制（MCP）。

`deepwrite.json` 新增 `bookType: "academic"` 分支（`kind: "deepwrite.book"`）：

| 字段 | 类型与含义 |
| --- | --- |
| `bookType` | `"academic"` |
| `subtype` | 学术文体子类型枚举（见 2.2） |
| `citationStyle` | 引用体例枚举：`gbt7714` \| `apa` \| `ieee` \| `latex` \| `none` |
| `linkedMaterialIds` | `CatalogId[]`（直接按库 ID 列表绑定，去重有序） |
| `linkedSkillIds` | `CatalogId[]`（直接按库 ID 列表绑定，去重有序） |
| `foundation` | 研究底座清单：`thesisOverview`、`terminology` 两份固定文档 + `cards`（文献与证据卡索引） |
| `frameworkStages` | 本作品论证框架阶段配置（`id`、`title`、`description`、`enabled`）及对应阶段文档 |
| `manuscript` | 正文目录：`chapters`（可选章容器列表）+ `sections`（节列表，每节含 `chapterId?`、`wordCountRequirement`、`brief`、`body`、`state` 三份文档引用） |

模板契约（`packages/contracts/src/book-templates.ts`）的 `BookTemplateDraftSchema` 同步增加 `workspaceType: "academic"` 分支，保存子类型、引用体例、默认开启阶段、资料库绑定与可选 `linkedAgentTeamIds`。

### 2.2 文体子类型与预设阶段

新建学术作品时选择子类型，自动预设默认开启的论证阶段、正文目录层级及初始末尾 `参考文献` 节（用户可在作品内随时开关、拖拽排序、修改阶段交付说明或增删自定义阶段）：

| 子类型 ID | 名称 | 默认正文层级 | 默认开启的论证框架阶段 | 默认引用体例 |
| --- | --- | --- | --- | --- |
| `empirical_paper` | 实证 / 理工论文 | 单层节（含摘要、参考文献） | 立题与文献脉络 → 方法与理论框架 → 实验与论据规划 → 全文论证大纲 | `ieee` 或 `gbt7714` |
| `humanities_paper` | 人文社科论文 | 单层节（含摘要、参考文献） | 立题与文献脉络 → 方法与理论框架 → 实验与论据规划 → 全文论证大纲 | `gbt7714` 或 `apa` |
| `literature_review` | 文献综述 | 单层节（含摘要、参考文献） | 立题与文献脉络 → 方法与理论框架（分类体系） → 实验与论据规划（对比矩阵） → 全文论证大纲 | `gbt7714` |
| `thesis_dissertation` | 硕博学位论文 | **章 → 节两级**（含中英文摘要、参考文献） | 全部 4 个阶段开启 | `gbt7714` |
| `proposal_grant` | 开题 / 基金申报 | 单层节 | 立题与文献脉络 → 方法与理论框架（技术路线） → 实验与论据规划（可行性与创新点） → 全文论证大纲 | `gbt7714` |
| `tech_report_article` | 学术解读 / 技术报告 | 单层节 | 立题与文献脉络（核心洞见与受众） → 全文论证大纲（降维叙事提纲） | `none` |

内置的 4 个学术论证框架阶段定义（独立于小说的 `DEFAULT_CREATIVE_PLOT_STAGES`）：

1. **`problem_and_gap`（立题与文献脉络）**：梳理研究领域的学术演进流派与代表路线，指出已有方案的边界，导出本文聚焦的 Research Gap，明确不做什么。
2. **`method_framework`（方法与理论框架）**：定义问题形式化符号、核心模型架构/算法流程，或社科理论视角、分析维度与核心研究假设，写清关键设计的理由（Rationale）。
3. **`evidence_plan`（实验与论据规划）**：建立「核心贡献 ↔ 证据/实验」一一映射表，规划数据集/案例来源、对比基线、消融或稳健性检验、图表清单（Figure/Table 占位与预期结论）及研究局限性。
4. **`argument_outline`（全文论证大纲）**：切分具体章/节结构，明确每节核心论点（Takeaway）、上下节承接逻辑、分配的文献/证据卡 `key`、图表编号与目标字数。

### 2.3 三层内容区细节

#### 第一层：研究底座（Foundation）

- **`研究立意与核心贡献`（`id = thesis_overview`）**：记录研究问题（RQ）、核心主张/方法一句话概括、不超过 3 条可证成的核心贡献、目标期刊/会议/学位或读者约束。
- **`术语与符号表`（`id = terminology`）**：维护全文统一的专业术语中英对照、缩写首次展开规范、数学符号定义表。
- **`文献与证据卡`（`kind = reference_card`）**：结构化条目列表，每张卡对应独立 Markdown 文件：
  - `id`：系统稳定 ID；
  - `citeKey`：作品内唯一的短引用键（如 `vaswani2017`、`smith2023_survey`、`exp_ablation_main`，仅字母、数字、下划线、连字符与冒号）；
  - `cardType`：`"literature"`（参考文献题录、核心结论、方法局限、与本文关系）或 `"evidence"`（已核实的实验结果表、统计口径、访谈/史料证据）；
  - `title`：展示标题（如 `Vaswani et al., 2017 - Attention Is All You Need`）；
  - 支持用户手动新建、从已绑定素材库勾选条目一键转为卡片，或由智能体提议创建/修改。

#### 第二层：论证框架（Framework Stages）

- 仅存放结构化论证思路、公式骨架、实验矩阵与章节规划，不直接堆写正式论文段落。

#### 第三层：正文编写（Manuscript）

- **单层与两级无缝切换**：
  - `chapters` 为空时展示为单层有序小节列表；
  - 新建“章（Chapter）”后，小节可挂载到指定 `chapterId` 下形成「章 → 节」两级树（硕博大论文默认初始化章节点，单篇作品中途也可随时新增章升级为两级，无需迁移作品类型）。
- **每节三联文档（`section`）**：
  - **`brief`（写作指引）**：本节核心论点、必引 `citeKey` 列表、图表规划、篇幅目标（从大纲落位，撰写大论文后半程时无需重读前文数万字）；
  - **`body`（正文）**：正式学术 Markdown（支持行内/块级 LaTeX 公式、表格、正文插图）；
  - **`state`（节末状态）**：记录本节首次定义的缩写与符号、实际引用的 `citeKey`、已兑现论点及对后文的跨节承诺（如“证明见附录 A”“消融分析见 4.3 节”）。
- **文末 `参考文献` 节**：需要引用的子类型默认在正文末尾创建标题为 `参考文献`（英文 `References`）的小节；智能体根据正文实际引用的 `literature` 卡片与作品 `citationStyle` 生成/更新格式化题录，用户可直接手动微调，导出时作为常规小节勾选导出。

## 3. 资料库自由共享与分组改造

### 3.1 分类标签（预设精简 + 允许自定义）

分类仅用于左侧列表徽标展示与搜索筛选，**不再限制分组槽位、不再限制条目 `stageId`、不再限制作品绑定**：

- **默认预设标签（保持精简）**：
  - 素材库：`文献`、`数据`、`设定`、`案例`、`其他`（已有老库的 `character / gimmick / plot / draft / mixed / other` 自动映射并兼容显示，不丢数据）；
  - 技能库：`通用`、`论证`、`规范`、`其他`（已有老库的 `general / plot / style / other` 自动映射兼容）。
- **自定义标签**：新建或编辑素材库、技能库时，除点选预设外，允许直接输入自定义短标签（`customTag`，1～24 字符）。
- **条目阶段解耦**：移除 `libraryProjectDialogOptions.ts` 中按库 `kind` 硬过滤条目阶段的限制；新建条目默认归入通用阶段即可。

### 3.2 分组自由组合（`MaterialLibraryGroup` & `SkillLibraryGroup`）

- 将分组清单成员从固定分类槽位对象改为有序去重数组 `memberIds: CatalogId[]`，同一分组可容纳任意标签、任意数量的库（如一个“课题组资料组”同时包含 3 个文献库 + 2 个实验数据库）。
- **向后兼容**：读取磁盘旧清单时，若存在旧 `members: { character, gimmick, ... }` 对象而无 `memberIds`，预处理自动按原槽位顺序提取非空 ID 转为 `memberIds`。

### 3.3 跨文体自由绑定与同步兼容

- **绑定界面统一**：短篇、剧本、长篇、学术四类作品的资料库绑定弹窗取消 `materialType` / `skillType` 过滤，展示用户全部素材库/技能库（支持按标签筛选、按分组一键勾选整组成员）。
- **智能体读取打通**：`prompts-material.ts`、`catalog-tools.ts` 等运行时读取逻辑直接以作品已绑定的库列表为准，不再按小说专属 `readAccess` 子类过滤掉自定义标签库。
- **持久化与双端同步兼容**（严格遵循 [error/schema-compat.md](../error/schema-compat.md)）：
  - 短篇、剧本、长篇已有清单继续兼容 `linkedMaterialIdsByKind` / `linkedSkillIdsByKind`（自定义标签库在旧桶结构中归入 `other` 桶，避免破坏旧版清单校验）；学术作品直接使用扁平 `linkedMaterialIds` / `linkedSkillIds`。
  - `packages/contracts/src/device-sync/`（含 `dependencies.ts`）同时解析新旧分组字段与 `academic` 作品依赖；涉及 `deepwrite.json` 严格 schema 的改动必须同步更新 `deepwrite-app` 镜像 schema 并联动验证。

## 4. 学术主创智能体设计

### 4.1 系统提示词分层（对齐 `docs/主要智能体系统提示词.md`）

| 层级 | 可编辑 | 内容与职责 | 位置 |
| --- | --- | --- | --- |
| 1. 基础准则 | 否 | 身份、指令优先级、事实边界、回复语言（跟随 `promptLocale`） | `pi-runtime-adapter/src/prompts-base.ts` |
| 2. 学术角色提示词 | **是** | 主创定位、工作方式（先沟通思路→逐层拆框架→按指引分节写→更新状态）、学术行文质量标准（高信息密度、因果严密、去套话排比、结论不超出证据边界）。提供中英双语并在 `builtin-agent-prompts.ts` 登记指纹 | `contracts/src/agent-prompts/academic.ts` |
| 3. 学术工作区规则 | 否 | 轻量目录树说明、对象稳定 ID 寻址规则、读写工具用法、**防幻觉死线**（禁止捏造未核实文献与实验数值，缺失一律打 `[待补引用: ...]` / `[待补数据: ...]` 占位） | `pi-runtime-adapter/src/prompts-academic-rules.ts` |
| 4. 引用体例硬约束 | 否 | 按当前作品 `citationStyle`（GB/T 7714 / APA / IEEE / LaTeX / 无限制）规定正文内引用格式与文末题录规范，自定义提示词与技能不可覆盖 | `contracts/src/academic-citation-style.ts` |
| 5. 写入审批与插图规则 | 否 | 自动保存或提案审批说明；编辑正文保留已有 `deepwrite-image://` 图片引用 | `write-approval.ts`、`prompts-book-images.ts` |
| 6. 联网与管理工具 | 否 | 仅在本轮开启联网搜索或资料库/团队管理工具时追加；联网查到的文献线索须核实并提议建卡后方可正式引用 | `web-search/prompt.ts` |

在「设置 → 智能体」中新增独立的 **「学术智能体」** 设置面板（模型配置、思考等级/温度、可编辑角色提示词与“恢复默认”）。

### 4.2 工具面与参数校验边界

复用短篇/长篇成熟的统一 CRUD 模式，共开放以下核心工具：

| 工具 | 作用与约束 |
| --- | --- |
| `read` | 按稳定 `kind` + `id`（及小节 `document = brief \| body \| state`）经 Core 只读桥按需读取；支持全文读取（授予本轮完整读取编辑凭据）及 `head` / `tail` 片段预览（用于大论文快速看相邻节衔接，不授予整篇覆盖凭据） |
| `search` | 作品内全文关键词检索（覆盖底座、文献/证据卡、框架阶段与全部章节正文），返回命中对象 ID、标题与上下文摘录，支撑 5～10 万字大论文的一致性与引用核查 |
| `create` | 新建文献/证据卡（`reference_card`）、自定义论证阶段（`framework_stage`）、章容器（`chapter`）或正文小节（`section`） |
| `edit` | 修改底座文档、卡片、框架阶段、章标题或小节的 `brief` / `body` / `state`（支持整篇覆盖与 `replacements` 局部替换；覆盖非空内容前须已完整读取） |
| `delete` | 删除指定卡片、自定义阶段、空章或小节（走可审阅/可恢复提案） |
| `query_linked_material_entries` | 列出、检索、按需读取已绑定的全部素材库条目 |
| `load_skill` | 按需加载已绑定的技能库方法论条目 |
| `ask_user_question` | 目标、研究假设、核心数据口径不明确且猜错会造成返工时简短提问（子智能体不提供） |
| `spawn_subagent` | 团队模式开启时调度当前学术作品生效团队中的已启用成员 |

遵循 [error/tool-args-validation.md](../error/tool-args-validation.md) 与 [error/limit-mismatch.md](../error/limit-mismatch.md)：工具 JSON Schema 只约束结构，字数与批量上限常量统一从 `@deepwrite/contracts` 导出并在说明文字标注，在 `execute` 内逐项校验并返回精确字段错误。

### 4.3 上下文预算与剪枝恢复（支撑 5～10 万字大论文）

- **每轮固定上下文（轻量快照）**：仅注入作品标题、子类型、引用体例、`AGENTS.md`、底座两份文档字数状态、文献/证据卡轻量目录（`citeKey + cardType + title + 字数`，不注入卡片正文）、论证阶段列表、章→节目录树（含每节 `brief / body / state` 字数状态）以及用户当前正在查看的焦点对象定位。
- **剪枝与摘要恢复**（扩展 `workspace-context-policy.ts` 的 `"academic"` 任务策略）：
  - 超过工作预算 50% 时剪枝旧轮大段 `read` 原文与旧写入参数正文；
  - 触发检查点摘要后，自动补回本会话已加载的技能（`skills`）、`术语与符号表`（控制在预算上限内）以及当前撰写小节末尾 1,500 字，防止长文续写术语漂移。

## 5. 学术智能体团队独立管理与默认团队

### 5.1 独立团队分类（`packages/contracts/src/agent-team-catalog.ts`）

1. `AgentTeamWorkspaceTypeSchema` 扩展为 `z.enum(["short", "script", "long", "academic"])`。
2. `EnabledAgentTeamIdsSchema` 新增可选字段 `academic: AgentTeamProfileIdSchema.optional()`。
3. 新增 `AcademicAgentTeamSettingsSchema`（`workspaceType: "academic"`），支持团队包导出/安装、新建作品与模板绑定（`agentTeams.setBookBinding`）。
4. **配置平滑升级**：`AgentTeamConfigStore` 读取现有 `agent-team-profiles.json` 时，若尚无 `workspaceType === "academic"` 的团队档案，自动补建一套内置的 **「默认学术团队」** 并写回，不改动用户已有的短篇、剧本、长篇团队及启用状态。

### 5.2 内置「默认学术团队」成员设计（默认均不勾选 `enabled: false`）

内置 5 个职责互不重叠的成员，全部默认 `enabled: false`，由用户按需勾选启用：

| ID | 名称 | `agentMode` | `webSearchMode` | 职责与硬边界 |
| --- | --- | --- | --- | --- |
| `literature_curator` | 文献与证据整理员 | `standard` | `inherit` | **只管底座建卡，不改大纲与正文。** 按主创指定的子课题检索已绑定素材库（开启联网时可辅助核查真实题录），提议创建或补充规范的 `reference_card`；缺失的年份、期刊、数值如实留空并说明，严禁补造。 |
| `section_drafter` | 章节撰稿员 | `standard` | `off` | **按指引闭卷写指定小节。** 先读 `terminology`、目标节 `brief`、点名的 `reference_card` 与相邻节 `state`；只写该节正式 `body` 并同步更新该节 `state`。强制关闭联网杜绝野生引用；缺证据处标 `[待补引用/数据: ...]`，不擅自改大纲或新建小节。 |
| `peer_reviewer` | 同行审稿人 | `pure-read` | `off` | **Reviewer #2 逻辑与方法论挑刺。** 纯只读不改稿；审查研究问题与贡献闭环、过度声称（结论超出证据支撑）、基线/消融缺失、因果跳步与相关工作边界模糊，输出 Major / Minor 分级问题、对象定位与最小修改建议。 |
| `citation_auditor` | 引用与一致性核查员 | `pure-read` | `off` | **全文规范与连续性体检。** 优先用 `search` 定位核查：① 正文引用与底座文献卡、`参考文献` 节是否双向闭合（无假引、漏列、列而未引），引用体例是否统一；② 数学符号、术语译名与首次缩写是否前后冲突；③ 跨节承诺（章节/图表交叉引用）是否兑现。 |
| `academic_polisher` | 学术润色编辑 | `standard` | `off` | **去 AI 味与学术表达精炼。** 仅润色主创指定的现有小节 `body`：在不改动任何数据数值、公式符号、引用标记与核心论点的前提下，消除排比套话、生硬连接词与翻译腔，使用 `replacements` 或整节替换提交审阅。 |

子智能体启动时与短篇/长篇一致：自动注入按本轮已提交提案刷新后的实时学术目录树、工作区规则与引用体例硬约束（`pure-read` 成员仅注入定位与读取规则）。

## 6. 第一版导出设计（`.md` 与 `.docx`）

在学术作品右键菜单与顶栏提供「导出稿件」弹窗（后续迭代可在此弹窗扩展投稿套件与发布衍生稿）：

- **范围选择**：按章/节树勾选要导出的内容（默认全选非空正文节，含摘要与末尾 `参考文献` 节；支持可选是否导出章标题层级）。
- **格式支持**：
  1. **Markdown（`.md`）**：按章（`#`）→ 节（`##`）→ 节内子标题规范拼接为 UTF-8 `.md` 文件；若含本地正文插图，支持导出为同目录带 `assets/` 资源文件夹或单文件文本。
  2. **Word（`.docx`）**：复用并增强 `apps/desktop/src/main/short-manuscript-docx.ts` 的自研 OOXML 打包链路，补齐学术排版要素：
     - 章标题、节标题与节内 `###` 子标题映射为 Word 标准样式 `Heading1` / `Heading2` / `Heading3`（便于 Word 自动生成目录）；
     - Markdown 表格解析为标准 `<w:tbl>` 表格（带表头与上下框线）；
     - 正文插图及图注居中输出（复用 `manuscript-export-images.ts`）；
     - 行内与块级公式、代码块保持清晰可读的段落/等宽排版，不丢失符号。

## 7. 界面与架构边界约束

1. **进程与协议顺序**：严格按 `packages/contracts` → `apps/desktop/src/preload` → `apps/desktop/src/main` → `apps/desktop/src/utilities` 顺序推进；Renderer 仅从 `@deepwrite/contracts/renderer` 引入运行时常量。
2. **包体积与 `WorkspaceShell.vue` 预算**（遵循 [error/budget-exceeded.md](../error/budget-exceeded.md)）：
   - 新建学术作品弹窗、框架阶段配置弹窗、文献/证据卡管理抽屉、学术导出弹窗及学术智能体设置面板全部注册到 `lazyAppComponents.ts` / `lazyFeatureImports.ts` 异步按需加载；
   - 状态与生命周期抽出独立的 `useAcademicBookLifecycleCoordinator.ts` 与 `useAcademicConversationCoordinator.ts`，不在 `WorkspaceShell.vue` 堆叠内联逻辑；
   - 界面样式严格使用 `DESIGN.md` 现有语义主题变量，新建组件使用独立作用域或前缀类名，避免全局类名碰撞。
3. **外部控制（MCP）同步**：在 `tool-routes.ts` 白名单与 `extras/external-control/skill/SKILL.md` 中同步支持学术作品的读取、检索与带版本校验提案写入，运行占用时返回 `external.busy`。
