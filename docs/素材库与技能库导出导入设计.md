# 素材库与技能库导出导入设计

> 状态：第 2 节的决定已于 2026-10-09 确认，同日实现 M0–M2，实现记录与验证见第 11 节。本文是实现依据；后续修改如需偏离，先改本文再改代码。

> 一句话：素材库、技能库和它们的分组可以从“⋯”菜单导出成一个 ZIP。包里每个条目是一份以标题命名的 Markdown 文件，离开 DeepWrite 也能直接阅读和使用。导入支持 ZIP 和文件夹：先识别其中的库、分类和条目，显示预览，用户确认后才建库。两台电脑之间私下分享素材和技能，导出后再导入即可，不需要账号或网络。

## 1 背景与目标

在此之前，素材库和技能库只能在本机 DeepWrite 里使用。想把一组素材或技能分享给别人，或者拿到其他软件里用，只能去翻工作区文件夹。这些文件夹是给程序读写的，不适合直接阅读：

- 条目文件名是内部 ID（`entries/<id>.md`），标题、分类和顺序都存在 `deepwrite.json` 里；
- 分组文件夹里只有一个清单，成员库要按 ID 去别的文件夹找；
- 直接把文件夹复制给别人，对方“打开已存在素材库”后，会和原机项目共用同一批 ID。

一期目标：

- **导出**：素材库、技能库，以及素材分组、技能分组的“⋯”菜单新增“导出”。点击后直接选择文件夹，生成 `名称.zip`，不弹格式选择框，固定导出 Markdown。
- **导出内容清晰**：包结构按“库 → 分类 → 条目”组织，文件名就是条目标题，按库内顺序编号；每个库和分组附一份 `_说明.md`，写明用途、简介和目录。在 Obsidian、Typora、文本编辑器里打开，或上传到其他 AI 工具，都能直接看懂。
- **导入**：素材库、技能库栏目的“＋”菜单新增“导入素材包… / 导入技能包…”，支持 ZIP 和文件夹。可以识别两类来源，先预览，用户确认后才建库：
  - DeepWrite 导出包；
  - 按“文件夹 / 子文件夹 / 文本文件”整理的普通资料。
- **往返无损**：DeepWrite 导出的包再导入后，库名、类型、题材、简介、条目标题、分类、顺序和正文都与原库一致，空条目也保留。只有 ID 和时间戳会重新生成。
- **外部修改可回导**：在其他软件里改过的包（改正文、增删文件、改文件名）仍可导入，以磁盘上的文件为准。
- **删除旧版导入**：“导入旧版素材库 / 导入旧版技能库”及其命令、解析代码一并删除，新导入也不识别旧版压缩包。

一期不做：

- TXT、Word、EPUB、PDF 格式导出；
- “每库合并成一个文件”的导出布局；
- 按 Agent Skills 约定导出（每个技能一个文件夹加一份 `SKILL.md`）；
- 导入时合并进已有库，或覆盖、更新已有库；
- 拖拽导入；
- 整个素材库或技能库栏目一键全部导出；
- 普通文件夹里的 Word、PDF 识别（继续使用已有的“从文件或文件夹导入素材”）；
- 包签名、加密、在线分享链接。

## 2 设计决定（2026-10-09 已确认）

| # | 决定 | 说明 |
| --- | --- | --- |
| 1 | 只导出 Markdown，不弹格式选择框 | 点“导出”后直接选择文件夹。Markdown 本身就是纯文本，记事本也能打开 |
| 2 | 条目正文原样输出 | 不插入标题行，不删改 Markdown 标记。标题由文件名表达。技能正文开头的 `---` 头部原样保留，导回后也不会多出一行标题 |
| 3 | 每个包只有一个顶层文件夹 | 解压后只得到一个文件夹，不会把文件散落在当前目录 |
| 4 | 单分类库平铺，多分类库按分类建子文件夹 | 人设库这类只有一个分类的库，不再套一层“人设/”；综合库、剧情库按“剧情设计 / 剧情细化 …”分文件夹 |
| 5 | 文件名为“编号 + 标题” | 例如 `01 霸总男主.md`。编号保留库内顺序，否则文件管理器会按拼音或字母重排 |
| 6 | 附带 `deepwrite-package.json` | 记录分类、顺序、库类型和简介，用于无损回导，其他软件可以忽略。`_说明.md` 里写明它的用途 |
| 7 | 不导出内部字段 | 条目 ID、时间戳、市场来源、内置标记、项目版本号都不进包。导入一律新建，ID 重新生成；内置技能库导入后是普通可编辑库 |
| 8 | 导出时选择文件夹，不选文件名 | 自动命名为 `库名.zip` 或 `分组名.zip`；重名时加 ` (2)`、` (3)`，从不覆盖已有文件 |
| 9 | 导入先预览后写入 | 识别过程只读；用户确认后由 Core 在一次事务里建好所有库和分组，失败时不留下建了一半的库 |
| 10 | 导入只新建 | 与已有库重名时自动加序号；不合并进已有库 |
| 11 | 彻底删除旧版导入 | 删除“导入旧版素材库 / 技能库”菜单、`catalog.importLegacyLibrary*` 命令和旧版解析代码；“＋”菜单换成“导入素材包… / 导入技能包…”。“从文件或文件夹导入素材”（往已有库里加条目）保留 |
| 12 | 来源内容以文件为准，清单只补充元数据 | 清单里有、磁盘上没有的条目跳过；磁盘上有、清单里没有的文件当作新增条目；正文一律取磁盘上的文件内容 |

## 3 用户流程

### 3.1 导出

入口：

- 素材库、技能库节点的“⋯”菜单，在“复制”之后新增“导出”；库文件夹缺失（不可用）时不显示。
- 素材分组、技能分组节点的“⋯”菜单，在“复制”之后新增“导出”；分组不可用时不显示。
- 内置技能库也可以导出，因为导出不修改库。

步骤：

1. 点“导出”。Renderer 先保存这些库里未保存的修改，沿用复制前的 `prepareLibraryProjectsForDuplicate`（带 `operation: "export"`）。保存失败或有冲突时停止导出，提示“导出已取消”。
2. Main 先向 Core 读取库或分组，这样库不可用等问题在选文件夹之前就会报出；然后弹出系统的选择文件夹对话框（可新建文件夹，按钮为“导出到这里”）。用户取消时什么都不提示。
3. Main 生成 ZIP 并写入所选文件夹，toast 提示“已导出到 …/都市爽文人设.zip”。分组里有成员库不可用时，写成“已导出到 …（1 个成员库不可用，未导出）”。
4. 失败时 toast 报错，并附上具体原因。

导出不设置页面级 pending，侧边栏和其他控件不受影响；连续点击由协调器内部丢弃。

### 3.2 导入

入口：素材库、技能库栏目“＋”菜单的“导入素材包… / 导入技能包…”。

1. **选择来源**：弹窗给出“选择 ZIP 压缩包”和“选择文件夹”两个按钮。分成两个按钮，是因为 Windows 和 Linux 的系统对话框不能在同一个窗口里同时选择文件和文件夹。识别期间，被点的按钮显示“正在识别…”，两个按钮都禁用。

2. **识别结果**：Main 记住所选路径，Core 只读扫描并识别，返回预览。预览只含标题和统计，不含正文。

   ```text
   ┌──────────────────────────────────────────────────────┐
   │ 都市爽文素材组.zip                                 × │
   │ 导入素材包                                           │
   │ DeepWrite 导出包 · 可完整还原                        │
   │ ☑ 建立分组  [都市爽文素材组            ]             │
   │ ┌──────────────────────────────────────────────────┐ │
   │ │☑ [都市爽文人设      ]              人设素材库    │ │
   │ │   12 条 · 48 KB                                  │ │
   │ │☑ [都市爽文剧情      ]              剧情素材库    │ │
   │ │   31 条 · 210 KB · 剧情设计 9 · 剧情细化 22      │ │
   │ │☑ [都市爽文梗        ]              梗素材库      │ │
   │ │   7 条 · 12 KB                                   │ │
   │ │   已有同名库，将命名为“都市爽文梗 (2)”           │ │
   │ └──────────────────────────────────────────────────┘ │
   │ ▸ 跳过 3 个文件：不支持的格式 2 · 空文件 1           │
   │                         [重新选择]  [导入 3 个库]    │
   └──────────────────────────────────────────────────────┘
   ```

   - 识别方式显示为一行稳定说明：“DeepWrite 导出包 · 可完整还原”“普通文件夹 · 已按文件夹结构识别”或“清单无法读取，已按文件夹结构识别”。
   - 每个库都可以取消勾选、修改名称。普通文件夹识别出的库，还可以用 `PopupSelect` 改库类型；改类型后，条目分类按第 5.4 节的规则重新归类，分类统计随之刷新。导出包的库类型取自清单，不能修改。
   - “建立分组”是否默认勾选、能否勾选，见第 5.4 节。不能勾选时，用一行稳定说明写明原因，例如“分组里每种类型只能有一个库，请调整库类型或取消部分库”。
   - 包的领域与当前栏目不一致时（在素材库里选了技能包），说明行写“这是技能包，将导入到技能库”，照常导入。
   - 跳过的文件默认折叠，展开后显示文件路径和原因。

3. **确认导入**：只有“导入”按钮进入“导入中…”。成功后弹窗关闭，toast 提示“已导入 3 个库、50 个条目”，侧边栏刷新并选中第一个新库。如果来源在预览之后发生了变化，toast 提示“来源在识别后发生了变化，请重新选择。”，弹窗回到第 1 步。

识别失败时 toast 报错并附原因，例如压缩包损坏、加密、超过上限，或识别不出任何文本文件；弹窗停在第 1 步。

## 4 导出包格式

### 4.1 目录结构

单分类库（人设库只有“人设”这一个分类），条目平铺：

```text
都市爽文人设.zip
└── 都市爽文人设/
    ├── _说明.md
    ├── 01 霸总男主.md
    ├── 02 落魄千金.md
    └── deepwrite-package.json
```

多分类库按分类建子文件夹：

```text
都市爽文剧情.zip
└── 都市爽文剧情/
    ├── _说明.md
    ├── 剧情设计/
    │   ├── 01 退婚开局.md
    │   └── 02 打脸高潮.md
    ├── 导语设计/
    │   └── 01 前十秒钩子.md
    ├── 剧情细化/
    │   └── 01 身份反转细化.md
    └── deepwrite-package.json
```

分组下面每个成员库一个子文件夹，成员库内部的规则同上：

```text
都市爽文素材组.zip
└── 都市爽文素材组/
    ├── _说明.md                ← 分组说明：成员库及其类型
    ├── 都市爽文人设/
    │   ├── _说明.md
    │   └── 01 霸总男主.md …
    ├── 都市爽文剧情/
    │   ├── _说明.md
    │   └── 剧情设计/ …
    └── deepwrite-package.json  ← 整个包只有一份，在顶层
```

- 库或分组下没有条目时，仍会导出 `_说明.md` 和清单，导入后得到一个空库。
- 成员库顺序与侧边栏一致：素材分组依次为人设、剧情、梗、正文、其他；技能分组依次为通用、剧情设计、文风写作、其他。
- 分类文件夹按 `MATERIAL_STAGE_IDS` / `SKILL_STAGE_IDS` 的顺序排列，文件夹内按库内顺序编号。
- 分类文件夹名、`_说明` 文件名和文案使用当前界面语言（英文界面下为 `_README.md`）。回导时，分类以清单里的 `stageId` 为准，与文件夹名称和语言无关。

### 4.2 命名规则

分类文件夹名沿用界面现有的分类名称，中英文与 `catalogWorkspace` 文案一致：

| 领域 | 分类 ID | 中文文件夹名 | 英文文件夹名 |
| --- | --- | --- | --- |
| 素材 | `gimmick` | 梗 | Story ideas |
| 素材 | `character` | 人设 | Character concepts |
| 素材 | `pacing` | 剧情设计 | Plot design |
| 素材 | `intro` | 导语设计 | Opening design |
| 素材 | `plot_refine` | 剧情细化 | Plot refinement |
| 素材 | `draft_excerpt` | 优秀正文片段 | Prose excerpts |
| 素材 | `other` | 其他素材 | Other materials |
| 技能 | `character_design` | 人物技能 | Character skills |
| 技能 | `plot_design` | 剧情技能 | Plot skills |
| 技能 | `outline` | 大纲技能 | Outline skills |
| 技能 | `draft` | 正文专家编写技能 | Prose writing skills |
| 技能 | `expert_section_writer` | 分节写手技能 | Section writing skills |

这张表在 `packages/contracts/src/library-package/labels.ts`，导出和识别共用。

文件和文件夹名的处理规则（`file-names.ts`）：

- 把 `< > : " / \ | ? *` 和控制字符替换为空格，合并连续空白，去掉首尾的空格和句点；
- 避开 Windows 保留名（`CON`、`PRN`、`AUX`、`NUL`、`COM1`–`COM9`、`LPT1`–`LPT9`），遇到时在后面加 `_`；
- 长度上限：顶层和库文件夹 40 字，分类文件夹 12 字，条目文件名（不含编号和扩展名）60 字，避免在 Windows 上超过 260 字符的路径限制；
- 同一文件夹内重名（不区分大小写）时，依次加 ` (2)`、` (3)`；
- 编号宽度为 `max(2, 条目数的位数)`，编号与标题之间用一个空格；
- 标题清理后为空时，文件名用“未命名”。

### 4.3 条目文件内容

条目正文原样写入，编码为 UTF-8、无 BOM，Markdown 标记全部保留。导入时去掉 BOM，并把 CRLF 和 CR 统一为 LF。

### 4.4 `_说明.md`

库的 `_说明.md`：

```markdown
# 都市爽文人设

- 类型：人设素材库 · 短篇
- 题材：都市 / 追妻
- 条目：12 个
- 导出：2026-10-09 · DeepWrite 1.6.308

## 简介

（库简介原文；没有简介时写“无”）

## 目录

1. [霸总男主](<01 霸总男主.md>)（人设，1,203 字）
2. [落魄千金](<02 落魄千金.md>)（人设，986 字）

## 使用说明

- 每个条目是一个独立的 Markdown 文件……
- 导回 DeepWrite：在“素材库”栏目的“＋”菜单选择“导入素材包…”……
- deepwrite-package.json 只用于导回 DeepWrite 时还原分类、顺序和库信息，其他软件可以忽略。
```

- 链接使用 `<…>` 形式，路径里的空格不必转义，原文也易读。
- 多分类库的目录按分类分成 `### 剧情设计` 等小节，小节内单独编号。
- 字数统计不含空白字符。
- 技能库省略题材行。
- 分组的 `_说明.md` 列出成员库（类型 · 库名 → 链接到其 `_说明.md`，附条目数）。不可用的成员库也会列出，并注明“库文件夹不可用，未导出”。

### 4.5 `deepwrite-package.json`

```json
{
  "format": "deepwrite.library-package",
  "formatVersion": 1,
  "generator": "DeepWrite 1.6.308",
  "exportedAt": "2026-10-09T08:00:00.000Z",
  "domain": "material",
  "group": {
    "title": "都市爽文素材组",
    "members": { "character": "lib-1", "plot": "lib-2" }
  },
  "libraries": [
    {
      "key": "lib-1",
      "directory": "都市爽文人设",
      "title": "都市爽文人设",
      "libraryType": "short",
      "materialKind": "character",
      "parentGenre": "都市",
      "subGenre": "追妻",
      "overview": "……",
      "entries": [
        { "file": "01 霸总男主.md", "title": "霸总男主", "stageId": "character" }
      ]
    }
  ]
}
```

- 单库导出时没有 `group`；`directory` 为 `""`，表示就是包的顶层文件夹。
- 技能库用 `skillKind` 代替 `materialKind`，并且没有 `parentGenre`、`subGenre`。
- `key` 只在包内有效，用于把 `group.members` 和库对应起来。
- `file` 是相对库文件夹的路径，用 `/` 分隔；`entries` 的顺序就是库内顺序。
- 简介只存在清单里，并在 `_说明.md` 中原样展示。
- 读取时（`LibraryPackageManifestSchema`）各字段类型宽松，逐项校验，不认识的字段直接忽略：
  - `formatVersion` 高于当前版本时，报错“这个包由更新版本的 DeepWrite 导出，请升级后再导入”；
  - 清单损坏、或一个库都没有时，改按普通文件夹识别，并注明“清单无法读取”。

### 4.6 ZIP 规格

- `main/zip-writer.ts` 的 `createZip`：deflate 压缩，文件名带 UTF-8 标志位（通用标志第 11 位），时间取导出时刻；条目数不超过 65,535，不使用 ZIP64。
- 短篇 DOCX/EPUB 原有的只存储写入器 `createStoredZip` 已合并到同一文件，作为 `createZip` 的 `store` 模式，行为不变。
- 云备份的 `createZip` 仍是单独一份（deflate、未设 UTF-8 标志），迁移列为收尾项。
- 写入时先写同一文件夹下的 `名称.zip.part`，写完再改名，失败时删除，不会留下损坏的半个 ZIP。

## 5 导入识别规则

### 5.1 读取来源（`utilities/library-package/scan-source.ts`）

- **ZIP**：沿用 Core 的 `legacy-zip.ts` 读取器，保留 256 MB 文件上限、32 MB 单文件上限、zip-slip 与加密检查，本次新增：
  - `sizeOf(name)`：不解压就能拿到大小，超过 32 MB 的文件只计入跳过，不中断整次导入；
  - 没有 UTF-8 标志、按 UTF-8 解码又失败的文件名，改按 GB18030 解码（中文 Windows“发送到压缩文件夹”即属此类）。旧版长篇导入共用这个读取器，也一并受益。
- **文件夹**：最多扫描 20,000 个文件、深度 6 层，不跟随符号链接。
- **两种来源共同忽略**：`__MACOSX/`、`Thumbs.db`、`desktop.ini`、`node_modules/`，以及以 `.` 开头的文件和文件夹（含 `.DS_Store`、`.git/`）。
- **文本文件**：`.md`、`.markdown`、`.txt` 和清单。解码见第 5.5 节；文本合计超过 512 MB 时报错。
- **指纹**：每个路径加大小，文本文件再加内容 SHA-256，汇总成指纹，用于判断来源在预览后是否变化。
- **定位根目录**（`unwrapSourceRoot`）：所有文件都在同一个文件夹下时，自动进入这一层，并逐层重复，适应解压后又压缩一次的包。

### 5.2 识别顺序（`recognizeLibraryPackage`）

1. 根目录有 `deepwrite-package.json`，能通过校验，且至少有一个库：按 DeepWrite 导出包识别（第 5.3 节）。
2. 其他情况：按普通文件夹识别（第 5.4 节）。
3. 识别不出任何库：报错“没有找到可导入的 .md、.markdown 或 .txt 文件。”

### 5.3 DeepWrite 导出包

- 以清单为骨架：库、分组、库类型、题材、简介、条目标题、分类和顺序都取自清单。
- 正文一律取磁盘上的文件内容，在其他软件里改过的正文照常导入；清单列出的空文件作为空条目保留。
- 清单里有、磁盘上找不到的条目跳过，计入“清单中的文件不存在”。
- 库文件夹里有、清单没有记录的文本文件，作为新增条目追加到最深一层包含它的库末尾：
  - 标题取文件名，并去掉编号前缀；
  - 分类取所在的分类文件夹，找不到时用该库类型的默认分类；
  - 内容为空的这类文件跳过。

  所以在其他软件里改了文件名，导回后的效果是“原条目跳过 + 一个新条目”，正文不丢，只是排到最后。
- 清单里的值不合法时（类型不认识、标题为空等），这一项按普通文件夹的规则推断，其余照常。
- 分组按清单的 `group.members` 还原成员位置；用户取消某些库后，剩下的库仍按原位置放入分组。

### 5.4 普通文件夹

1. **划分库**：
   - 根目录下直接有文本文件（不含 `_说明`）：整个根目录是一个库，库名取根目录名；
   - 否则，每个含文本文件的一级子文件夹是一个库，库名取子文件夹名，根目录作为分组候选；
   - 一次最多 32 个库，超出部分跳过，并注明“只识别了前 32 个”。
2. **库里的分类**：库文件夹下的一级子文件夹按名称匹配分类，可匹配第 4.2 节的中英文名称，以及以下别名：
   - 素材：人物、角色 → 人设；脑洞、创意 → 梗；节奏 → 剧情设计；开篇、导语 → 导语设计；细纲 → 剧情细化；正文、范文、片段 → 优秀正文片段；
   - 技能：人物、人设 → 人物技能；剧情 → 剧情技能；大纲 → 大纲技能；正文 → 正文专家编写技能；分节 → 分节写手技能。

   匹配不上的文件夹，和更深层的文件，都并入这个库，使用默认分类；文件夹路径不进入标题。
3. **库类型（素材）**：
   - 先看库文件夹名里的关键词（人设、人物、角色 → 人设；梗、脑洞、创意、点子 → 梗；剧情、情节、大纲、节奏、开篇、细纲 → 剧情；正文、范文、片段、摘录 → 正文；其他 → 其他）；
   - 没有关键词时：全部条目都在同一种类型的分类文件夹里，就取这种类型；否则为综合（`mixed`），这样未分类的条目会落在“其他”。
4. **库类型（技能）**：名称含“剧情”为剧情设计技能库，含“文风”或“风格”为文风写作技能库，含“其他”为其他技能库，其余为通用技能库。
5. **分类归位**（`resolveLibraryPackageStage`）：分类必须在库类型允许的范围内（素材按 `MATERIAL_STAGE_KINDS`），否则改用默认分类，与现有“从文件或文件夹导入”的默认值一致：
   - 素材：人设 → `character`，梗 → `gimmick`，剧情 → `pacing`，正文 → `draft_excerpt`，综合、其他 → `other`；
   - 技能：剧情设计技能库 → `plot_design`，其余 → `draft`。
6. **标题**：取文件名，去掉扩展名。编号前缀只在两种情况下去掉：同一文件夹两个及以上文件都带“数字 + 空格 / 点 / 下划线 / 短横”前缀，或者编号以 0 开头（导出包的写法）。所以单独一个“1984 年的雨”不会被误删。标题超过 256 字时截断。
7. **顺序**：文件排在同级文件夹之前，同级按 zh-CN 自然排序（`2` 在 `10` 之前，汉字按拼音）。
8. **`_说明` 文件**：库根目录下的 `_说明.md/.txt` 或 `_README.md/.txt` 不作为条目，其“简介 / Overview”一节作为库简介，即使清单丢失也能保住简介。其他 `README.md` 当作普通条目。
9. **空文件**：跳过，计入“空文件”。
10. **分组**（`assignLibraryPackageGroup`）：
    - 识别出 2 个及以上的库时，根目录作为分组候选，分组名取根目录名；
    - 每种类型只能放一个库，综合素材库依次填入空位（其他、人设、剧情、梗、正文）；技能库只能放入同类型的位置；
    - 能放下时，“建立分组”默认勾选；放不下时不能勾选，并写明原因。用户在预览里改了类型后，会实时重新判断。

### 5.5 文本解码

1. 有 UTF-8 BOM，或能按 UTF-8 严格解码：按 UTF-8 读取。
2. 有 UTF-16 LE / BE 的 BOM：按 UTF-16 读取。
3. 以上都不是：按 GB18030 严格解码，覆盖中文 Windows 记事本保存的“ANSI”文件。
4. 仍然失败，或解码后含有 NUL 字符：跳过，计入“无法识别编码”。

### 5.6 跳过与上限

预览中的跳过原因包括：不支持的格式、空文件、超过 32 MB、无法识别编码、清单中的文件不存在、不属于任何库、超出数量上限（单库超过 4,096 个条目或超过 32 个库）。

单个库的正文合计超过 128 MB 时，这个库在预览里不能勾选，并写明原因；Core 导入时会再检查一次。

## 6 进程与协议

### 6.1 命令

| 命令 | 方向 | 载荷 → 结果 |
| --- | --- | --- |
| `catalog.exportLibraryPackage` | Renderer → Main | `{ domain, target: { type: "library" \| "group", id } }` → `{ status: "cancelled" }` 或 `{ status: "saved", filePath, libraryCount, entryCount, skippedLibraryCount }` |
| `catalog.readLibraryPackageSource` | Main → Core（内部） | 同上输入 → 分组名、成员（位置 + 完整库，不可用为 null）；只读 |
| `catalog.chooseLibraryPackageSource` | Renderer → Main | `{ domain, sourceKind: "zip" \| "directory" }` → `null`（取消）或 `{ previewId, expiresAt, preview }` |
| `catalog.previewLibraryPackageAtPath` | Main → Core（内部） | `{ sourcePath, sourceKind, domain }` → `{ preview, sourceFingerprint }`；只读 |
| `catalog.importLibraryPackage` | Renderer → Main | `{ previewId, choices }` → `{ domain, groupId?, libraryIds, entryCount }` |
| `catalog.importLibraryPackageAtPath` | Main → Core（内部） | `{ sourcePath, sourceKind, domain, expectedFingerprint, choices, parents }` → 同上 |
| `catalog.discardLibraryPackagePreview` | Renderer → Main | `{ previewId }` → `{ discarded }`；关闭弹窗或重新选择时调用 |

- 3 条内部命令同时列入 `main/index.ts` 的内部命令拒绝列表和 `forbidden-commands.ts`，Renderer 无法直接发送。
- Preload 暴露 `window.deepwrite.libraryPackage`（`exportPackage`、`chooseSource`、`importPackage`、`discardPreview`），请求和响应都经过 schema 校验。
- 文件路径只在 Main 和 Core 之间传递：Main 用 `ImportPreviewRegistry` 把 `previewId` 对应到来源路径、来源类型、领域和指纹，预览 30 分钟后过期，窗口关闭时清理。
  - 这个登记表由原 `ContinuationImportPreviewRegistry` 通用化而来，续写导入改为继承它，行为不变。
- `choices`：

  ```text
  {
    libraries: [{ key, include, title, kind? }],
    createGroup,
    groupTitle?
  }
  ```

  `kind` 只对可改类型的库生效；Core 会用 `resolveLibraryPackageImport` 重新校验，分组放不下时拒绝。
- `parents` 由 Main 用 `workspaceResourceParent` / `workspaceGroupParent` 按包的领域算出，导入前要求已选定工作目录。

### 6.2 导出时序

1. Renderer 保存草稿后发送 `catalog.exportLibraryPackage`。
2. Main 先发送 `catalog.readLibraryPackageSource`。Core 读取 `deepwrite.json` 和条目文件，只读；分组里读不到的成员库记为 null；全部不可用时报错“没有可导出的内容”。
3. Main 弹出选择文件夹对话框，取消则返回 `cancelled`。
4. Main 用 contracts 的 `buildLibraryPackageFiles` 生成文件，`createZip` 打包，选一个不重名的文件名，经 `.part` 写入，返回 `saved`。

导出由 Main 写文件，与正文导出一致；Core 仍是本地项目和注册表的唯一写入者，导出不触碰它们。

### 6.3 导入时序

1. Renderer 发送 `catalog.chooseLibraryPackageSource`，Main 弹出对应的系统对话框。
2. Main 发送 `catalog.previewLibraryPackageAtPath`，Core 扫描、识别并生成预览，Main 登记 `previewId` 后返回。
3. 用户确认后，Renderer 发送 `catalog.importLibraryPackage`，Main 取出路径，发送 `catalog.importLibraryPackageAtPath`。
4. Core 重新扫描并比对指纹，不一致时以 `catalog.package_source_changed` 拒绝；一致时 `recognizeLibraryPackage` → `resolveLibraryPackageImport` → 写入（第 6.4 节）。
5. Main 释放这次预览并返回结果；Renderer 刷新目录，选中第一个新库。

### 6.4 Core 写入事务

`FolderCatalogStore.importLibraryPackage`：

1. 在同一个 `mutate` 里，由 `folder-catalog-store/library-package-import.ts` 生成全部新项目：新 ID、新时间戳、对已有库名和分组名去重（`nextLibraryPackageTitle`）、从不内置、不带市场来源。
2. 由新增的私有方法 `writeAndRegisterNewProjects` 依次写入项目文件夹，最后只写一次注册表。
3. 中途失败时删除本次已建的文件夹，注册表不变。

导入的库是普通库：参与双端同步、可以关联到作品，与手动新建的库没有区别。

### 6.5 上限汇总

| 项目 | 上限 | 依据 |
| --- | --- | --- |
| ZIP 文件 | 256 MB | `legacy-zip.ts` 现有上限 |
| 单个文本文件 | 32 MB | 与 `DEFAULT_MAX_MARKDOWN_BYTES` 一致 |
| 文本合计 | 512 MB | 防压缩炸弹 |
| 文件夹扫描 | 20,000 个文件，深度 6 层 | 防止误选大目录导致卡住 |
| 每库条目 | 4,096 个 | `CATALOG_PROJECT_MAX_CONTENT_ITEMS` |
| 每库正文 | 128 MB | 与 `DEFAULT_MAX_PROJECT_CONTENT_BYTES` 一致 |
| 一次导入的库 | 32 个 | `LIBRARY_PACKAGE_MAX_LIBRARIES` |
| ZIP 条目数 | 65,535 个 | 不使用 ZIP64 |

  - 跳过文件列表拆为 `ImportLibraryPackageSkipped.vue`；
  - 勾选、改名、改类型、分组判定和最终 `choices` 由 `useLibraryPackageImportForm.ts` 管理；

- 复选框受控：显示值来自数据，变更事件只上报。
