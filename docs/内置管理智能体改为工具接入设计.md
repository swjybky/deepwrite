# 内置管理智能体改为工具接入设计

2026-11-08 定稿。把创作空间里的三个内置管理子智能体（技能管理、素材管理、智能体团队管理）从“`spawn_subagent` 交接给子智能体”改为“启用后直接作为主智能体的工具”，三项默认关闭。

## 一、现状

- 设置：contracts `builtin-subagents.ts` 的 `BuiltinSubagentSettingsSchema`（`skill` / `material` / `team`，各含 `enabled`、`description`），默认 `enabled: true`。由 `AgentTeamConfigStore` 随团队目录持久化，界面是 `renderer/.../components/BuiltinSubagentSettings.vue`（在智能体团队页）。手机端 `deepwrite-app` 有同形状的镜像 schema（`src/core/agent-team/catalog.ts`、`core/library-agent/manager-settings.ts`）。
- Main：`ipc/session-commands.ts` 调用 `prepareLibraryManagementRunContext`（作品绑定库候选 + 每个启用领域的库智能体档案）和 `prepareTeamManagementRunContext`，结果放进 `agent.prompt` 载荷的 `libraryManagement` / `teamManagement`，并把作用域记到 activeRun，供 `internal-command-authorizer.ts` 校验 `catalog.queryLibraryManagement`、`agentTeams.*ActivePrompt`。
- Agent：`run-tools.ts` 把 `createLibraryManagementRuntime` / `createTeamManagementRuntime` 产出的定义并入 `spawn_subagent`；子智能体在 `prepareChild` 时拿到库工具（`buildLibraryAgentTools`，按 `library_id` 经 Core 读取目标库快照）或团队工具（`list_active_agent_teams`、`read_agent_team_prompt`、`propose_agent_team_prompt`）。主智能体提示词由 `libraryManagementParentPrompt`、`teamManagementParentPrompt` 注入“用 spawn_subagent 委派”。`subagent-task-plan.ts`、`subagent-child.ts`、`subagent-mode.ts` 对 `toolSource: "library-management" | "team-management"` 有特殊分支。

## 二、目标

1. 三项设置改名为“内置管理工具”，每项开关打开时，主智能体（短篇、剧本、长篇主智能体）本轮直接获得对应工具；关闭时不装配、不在提示词出现。
2. 不再产生这三个子智能体定义，`spawn_subagent` 中不再出现它们；团队成员子智能体也不获得这些工具（只给主智能体）。
3. 三项默认关闭。

## 三、设置与迁移

- 沿用持久化字段 `builtinSubagents` 与形状（`enabled`、`description`），不加字段，避免手机端严格 schema 解析失败。新的默认值：三项 `enabled: false`，`description` 改为工具调用说明（例如“仅当用户主动要求或明确确认在当前作品绑定的技能库中创建、记录、优化或编辑内容时调用这些工具……”）。
- 旧配置迁移沿用 `team` 字段已有的做法：在 schema `transform` 中，若某项的 `description` 等于旧默认文案（三项旧默认文案都要覆盖，含 team 的两个历史版本），视为用户未改动，整体替换为新默认值（即关闭 + 新说明）；用户改过说明的保留其 `enabled` 与说明。
- `description` 在工具模式下的用途：拼入该组工具的主智能体提示词段落，作为“何时调用”的说明。
- 界面 `BuiltinSubagentSettings.vue`：标题、各项名称、说明字段标签改为“内置管理工具 / 技能管理工具 / 素材管理工具 / 团队提示词管理工具 / 调用说明”，开关文案说明“开启后主智能体可直接调用”。中英文 i18n 同步。乐观更新、受控开关沿用现有实现（见 AGENTS.md 闪烁条目）。
- 常量：`BUILTIN_SUBAGENT_NAMES` / `BUILTIN_SUBAGENT_IDS` 若只服务于子智能体定义，删除或改名为工具组标识；`LIBRARY_MANAGEMENT_INVOCATION_POLICY`、`TEAM_MANAGEMENT_INVOCATION_POLICY` 中“调用子智能体”的措辞改为“调用工具”。

## 四、Main

- `prepareLibraryManagementRunContext`：只为启用的领域生成上下文；不再需要解析库智能体档案（`profile`），`LibraryManagementRuntimeContextSchema.managers` 改为启用领域列表 + 调用说明。作品绑定库范围、Core 查询、activeRun 作用域、授权校验和 `externalResourceIds` 保持不变。
- `prepareTeamManagementRunContext`：不变（已经只在启用时返回）。

## 五、Agent（`pi-runtime-adapter`）

### 素材 / 技能管理工具

- 复用上一期的 `library-agent-tools/domain-tools.ts` 包装模式：以作品绑定库为索引、`library_id` 选择目标库，首次访问经 `catalog.queryLibraryManagement`（作品作用域，现有授权）读取快照，本轮按库缓存工具状态（`reconcileLibraryToolState`）。抽出可注入“索引 + 加载函数”的公共包装，库页面智能体（`catalog.readLibraryAgentLibrary`）与这里共用，不复制逻辑。
- 与创作工具不重名：现有写作工具已有 `load_skill`、`read`、`edit`、`query_linked_material_entries` 等。管理工具不带 `load_skill`；其余工具若与主智能体现有工具重名，统一加前缀（如 `manage_material_*` / `manage_skill_*`），并检查长篇的 `buildLongRuntimeToolBoundary` 能列出这些工具。
- 写入：沿用库条目 / 库介绍提案（`library.editor_mutation` 事件），遵守本轮 `writeApprovalMode`。确认主智能体运行发出的这类事件能被 Renderer `library-staging.ts` 找到对应会话并进入审阅（之前来自子智能体，现在直接来自主运行）。
- 只读库（内置技能库）只读不写；未绑定的库不可访问。
- 库智能体档案里的元数据写作要求（如 `MATERIAL_METADATA_AUTHORING_GUIDANCE`）放进素材管理工具组的提示词段落或工具说明，保证创建素材时仍按规范写头部。

### 团队提示词管理工具

- `buildTeamManagementTools` 的三个工具直接加入主智能体工具集；读后才能提案、用户审阅后保存等规则不变。原子智能体系统提示词中的工作方法（先 list 再 read、保留成员职责、不把分析写进提示词、准确区分已保存 / 拒绝 / 冲突）并入该工具组的主智能体提示词段落。

### 清理

- `run-tools.ts`：`spawn_subagent` 的 `definitions` 只保留用户团队成员；删除管理子智能体的 `prepareChild` 分支。主智能体在没有团队成员时也能拿到管理工具。
- 删除 `toolSource: "library-management" | "team-management"` 及 `subagent-task-plan.ts`、`subagent-child.ts`、`subagent-mode.ts` 中只为它们服务的分支；`createLibraryManagementRuntime` / `createTeamManagementRuntime` 改为返回工具与提示词段落。
- 主智能体提示词：`libraryManagementParentPrompt`、`teamManagementParentPrompt` 改为描述工具（列出已绑定候选库、调用说明、调用政策），不再提 spawn_subagent。
- 外部控制、团队广场、子智能体看板、活动描述（`agentActivityDescriptors`、`conversationToolStatus`）里若依赖这三个子智能体 id 或名称，同步改为工具展示；新工具在对话中要有可读的状态文案。

## 六、不做

- 不改作品绑定范围：素材 / 技能管理工具仍只管理当前作品绑定的库。
- 不改素材库、技能库页面里的库智能体（上一期已改为全库管理）。
- 不改手机端；只保证桌面端持久化形状不变，手机端照常解析。若发现手机端也需要同样改动，在报告中列出，不在本次修改 `deepwrite-app`。

## 七、验证

- 单元测试：
  - 设置 schema：新默认三项关闭；三种旧默认文案迁移为关闭 + 新说明；自定义说明保留原开关。
  - Agent：开关关闭时主智能体工具集和提示词都不含管理工具；开启时含对应工具且 `spawn_subagent` 中没有管理子智能体；团队成员子智能体工具集中没有管理工具；工具名与主智能体现有工具不冲突（短篇、剧本、长篇各一例）。
  - 素材 / 技能工具：未绑定库拒绝、内置库拒写、按 `library_id` 懒加载、产生的提案带正确 `libraryId` 与 `baseProjectRevision`。
  - 团队工具：未读先提案被拒、用户拒绝不保存、接受后保存，均由主运行直接触发。
  - Renderer：主运行发出的库提案进入审阅；设置开关受控、失败回滚。
- 命令：`pnpm typecheck`、`pnpm lint`、`pnpm lint:boundary`、相关 `pnpm test`（`TMPDIR=/private/tmp`，默认临时目录有一项既有路径别名测试失败）、`pnpm build`（含语言数据预算）。
- 桌面实机由用户验收：开关默认关闭；开启后主智能体直接调用工具完成素材 / 技能条目创建与编辑、团队提示词修改的审阅与保存。
