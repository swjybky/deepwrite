# 作品绑定智能体团队设计

## 1. 目标

在“每种写作类型启用一个团队”的默认机制之外，增加一个**可选**的作品级绑定：

- 作品没有绑定团队：完全沿用原机制，使用“智能体团队”页启用的团队。
- 作品绑定了团队：团队模式**只使用绑定的团队**，启用的团队对这部作品不再生效；启用、关闭或切换启用团队都不影响它。
- 一部作品可以绑定多个团队，操作方式与技能库、素材库绑定一致。
- 新建作品、新建模板时都可以选择绑定，默认不选。

两种机制互斥，不做回退：绑定的团队失效时明确告知用户，不悄悄换回启用的团队。

## 2. 绑定存在哪里

绑定保存在本机 `config/agent-team-book-bindings.json`，由 Main 的 `AgentTeamConfigStore` 管理，**不写入作品的 `deepwrite.json`**。

| 对比项 | 写入作品清单 | 本机配置（采用） |
| --- | --- | --- |
| 团队 ID 含义 | 团队不参与双端同步，ID 只在本机有效，同步过去就是悬空引用 | 与团队目录同处一地，含义一致 |
| 手机端、旧版本 | `deepwrite.json` 与同步 schema 都是 strict，多一个字段就会拒收（`writeReceipts` 出过同样的问题） | 不改动作品清单和同步载荷 |
| 未绑定的作品 | 需要改清单 schema、迁移和同步镜像 | 文件不存在时等同没有绑定，行为与之前逐字节一致 |
| 权威来源 | Main 需经 Core 读取作品 | Main 直接解析，Renderer 只传作品 ID |

代价是绑定不随作品走：换一台设备或同步到手机后，这部作品使用该设备启用的团队。团队本身也不跟着走，这个边界是一致的。

## 3. 数据与协议

- `AgentTeamCatalogSnapshot` 增加可选字段 `bookBindings`（作品 ID → 团队 ID 列表）。它只存在于返回给调用方的快照中，写盘时剥离，`agent-team-profiles.json` 的格式不变，旧版本仍能读取。
- 新增命令 `agentTeams.setBookBinding`（`{ bookId, workspaceType, teamIds }`），`teamIds` 为空即解除绑定。Main 校验团队存在且类型匹配，返回新的目录快照。
- `BookTemplateDraft` 增加可选字段 `linkedAgentTeamIds`，为空时不写入，已有模板不变。

### 共用解析规则

放在 contracts 的纯函数（`agent-team-book-binding.ts`），Main 运行与 Renderer 预览共用，避免两侧漂移：

- `activeAgentTeams(catalog, workspaceType, bookId)`：作品有绑定记录时 `source: "bound"`，只返回绑定且类型匹配的团队；否则 `source: "enabled"`，返回启用的团队。**只要存在绑定记录就不会回到启用团队。**
- `activeAgentTeamMembers(active, parentAgentId)`：按绑定顺序合并成员。
- `activeAgentTeamsParallel(active)`：所有团队都开启并行时才并行。

## 4. 多团队如何合并

运行请求要求子智能体的 ID、名称唯一，合计不超过 60 个。合并规则：

1. 只取当前主智能体下已启用的成员，按绑定顺序排列。
2. 完全相同的成员（同一个团队包安装两次）只保留一个。
3. 同 ID 或同名但内容不同的成员都保留：ID 追加序号，名称追加团队名，结果确定，不随运行变化。
4. 合计超过 60 个时拒绝运行并说明原因，不静默丢弃成员。

并行取最保守的值：只要有一个团队关闭并行，这部作品就串行。串行最多慢一些，而让按串行设计的团队并行可能打乱交接顺序。

## 5. 失效与边界

| 情形 | 行为 |
| --- | --- |
| 删除被绑定的团队 | 确认弹窗提示受影响的作品数；删除后从所有绑定中移除，某部作品的绑定清空时恢复默认机制 |
| 绑定的团队都没有当前主智能体的成员 | 团队模式不可用并说明原因，不回到启用团队 |
| 绑定文件中有已不存在的团队 ID | 解析时忽略；全部失效时同上，不回到启用团队 |
| 模板引用了已删除的团队 | 与失效的技能库、素材库一样，保存和创建时提示修改模板 |
| 永久删除作品 | 同时清除绑定记录；“移出工作区”保留绑定，重新加入后继续生效 |
| 复制作品 | 副本继承绑定，与技能库、素材库绑定一致 |
| 团队模式开关 | 不变。绑定只决定“团队模式用哪些团队”，不会强制进入团队模式 |

## 6. 界面

- **绑定入口：** 作品菜单在“技能库绑定”“素材库绑定”下增加“团队绑定”，短篇、剧本、长篇都有。
- **新建：** 新建作品弹窗和模板编辑器都有可选的绑定区块，默认不选，提示当前会使用哪个启用团队。按模板新建时摘要显示模板绑定的团队。
- **机制说明：** “智能体团队”页在“当前生效”下说明两种机制和合并规则，团队卡片显示绑定的作品数。
- **对话框：** 团队模式的说明、`#` 成员菜单都按当前作品实际生效的团队显示。

## 7. 验收

- 未绑定：运行解析结果、`agent-team-profiles.json`、作品清单都与之前一致，且不产生绑定文件。
- 已绑定：切换、关闭启用团队都不影响运行结果；解除绑定后立即回到启用团队。
- 绑定失效：不回退到启用团队。
- 多团队：成员合并、重名处理、超限拒绝、并行规则。
- 模板：保存与读取保留绑定；按模板新建时绑定写入本机配置，且不进入 Core 的创建命令。
