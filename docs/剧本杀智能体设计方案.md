# 剧本杀智能体设计方案

> 状态：设计定稿，已与 [学术写作智能体与资料库自由共享设计.md](学术写作智能体与资料库自由共享设计.md) 交叉印证对齐（2026-11-17），待拉独立 worktree 分期实施。
>
> 范围：新增独立创作空间「剧本杀」（内部标识 `mystery`），含独立领域存储、五阶段三栏工作台、主智能体与「默认剧本杀团队」、扁平跨文体资料库绑定，以及无剧透分册导出（`.md` / `.docx`）。

## 1. 目标与核心思路

剧本杀与线性叙事作品（短篇、影视剧本、长篇小说）的根本差异在于：**创作源头是单一客观的「上帝视角真相」，交付成品则是多个信息严格隔离的「主观角色本」加上公共搜证线索与 DM 主持手册。**

若直接沿用线性章节结构，AI 写作极易出现四大问题：**视角串戏泄密**（写出角色不在场或未知的真相）、**时空撞车**（甲乙两本时间地点对不上）、**断锤或爆凶**（关键推论漏投或过于直白）、**边缘位坐牢**（部分角色缺乏核心秘密或情感羁绊）。

本方案采用**「外轻内严」融合结构**（与学术方案“先给思路、拆解框架、带指引分步写作”的核心原则一致）：

1. **全题材通用**：支持 `硬核推理`、`情感沉浸`、`机制阵营`、`欢乐撕逼`、`恐怖变格`、`其他` 六类题材，结合盘面规格（人数、幕数、叙事人称）与自由标签资料库切换创作重心。
2. **上帝层整块化**：真相、核诡、全局时间线与 DM 手册采用整块 Markdown 文档，便于全局核对，避免细碎对象导致取证链过长与审批卡爆炸。
3. **多视角层卡片化隔离**：玩家人物本采用 `角色 × 幕次` 二维结构；每一幕成对绑定**「视角任务卡（内部知情边界）」+「人物本正文（玩家可见）」**，先锁死该角色本幕的知情范围再动笔。
4. **物理文件级防剧透**：所有内部设计稿（真相、角色底牌、每幕视角任务卡、DM 手册）与玩家可见稿（公开选角词、人物本正文、搜证卡面、公共序幕）在文件层严格分离，分册导出无需正则切分即可保证零剧透泄露。
5. **多智能体物理盲写与测本审计**：复用现有子智能体内核，`纯净·无工具（pure-bare）` 模式执行单角盲写（物理隔绝上帝真相，支持抽卡），`纯净·只读（pure-read）` 模式配合 `search` 执行全本撞车与断锤审计。

## 2. 与「学术写作方案」交叉印证后的隔离与复用边界

结合 [学术写作智能体与资料库自由共享设计.md](学术写作智能体与资料库自由共享设计.md) 及仓库工程红线（[budget-exceeded.md](../error/budget-exceeded.md)、[schema-compat.md](../error/schema-compat.md)、[mixed-worktree.md](../error/mixed-worktree.md)），两套新创作空间通过**「错位存储 + 共享新资料库底座 + 薄表驱动挂载」**实现零踩脚并行开发：

### 2.1 核心印证与对齐决策

| 维度 | 印证与对齐结论 |
| --- | --- |
| **存储错位隔离（零文件冲突）** | 学术作品进入 `contracts/src/catalog/` 与 `folder-catalog-store.ts`（`kind: "deepwrite.book", bookType: "academic"`）并同步手机端 schema；剧本杀因具备 `角色 × 幕次` 二维矩阵与多目录物料，沿用 `long-book` 模式走**独立 `mystery-store`（`kind: "deepwrite.mystery-book"`）**。两个并行 worktree 在契约、Core 存储与 `device-sync` 层完全错开，零合并冲突。 |
| **资料库扁平绑定对齐** | 对齐学术方案第 3 节的资料库松绑改造：剧本杀不背旧小说的五桶 `linkedMaterialIdsByKind` 包袱，清单直接采用与 `academic` 完全一致的扁平去重有序数组 **`linkedMaterialIds: CatalogId[]` 与 `linkedSkillIds: CatalogId[]`**，直接共享自定义标签库（如 `核诡`、`法医考据`、`沉浸演绎`）、自由分组与统一跨文体绑定弹窗。 |
| **插图、版本与 `.docx` 复用** | 增量接入现有 `book-images`（作品根下 `images/*.png\|jpg`，支撑搜证现场图、尸检图、地图卡插入及 `prompts-book-images.ts` 编辑保护）与 `document-versions`（单文档历史恢复）；分册导出除 `.md` 外，复用自研 OOXML 打包链路支持 `.docx` 导出（便于线下打印装订）。 |
| **团队配置平滑升级同构** | 对齐仓库现有 `long` 与 `academic` 惯例：内置团队命名为 **`「默认剧本杀团队」`**，初始 `parallelSubagents: false`、所有成员默认 `enabled: false` 且关闭野生联网（`webSearchMode: "off"`）。`AgentTeamConfigStore` 统一按缺失的 `workspaceType` 自动补建对应默认团队档案，两边任意顺序合入均互不覆盖。 |

### 2.3 公共薄注册点与双 Worktree 合入顺序

公共文件仅做并列枚举或单行分发（与 `academic` 合并时仅为相邻行追加）：

1. **创作空间导航与懒加载工作台**：侧栏注册 `mystery`；`lazyAppComponents.ts` / `lazyFeatureImports.ts` 异步注册 `MysteryWorkspaceModule.vue` 与弹窗/设置面板，状态收进独立的 `useMysteryBookLifecycleCoordinator.ts` 与 `useMysteryConversationCoordinator.ts`，严守 `WorkspaceShell.vue ≤ 2800` 行与启动包体积预算。
2. **契约总表、Preload 与 IPC**：`CommandEnvelopeSchema` 并入 `MysteryCommandSchemas`，`window.deepwrite.mystery` 暴露桥接，`dispatch-command.ts` 串接 `handleMysteryCommands`（纳入版本历史与图片引用解析分支）。
3. **会话编排与上下文剪枝**：`session-commands.ts`、`workspace-run-plan.ts`、`workspace-context-policy.ts` 增加 `"mystery"` 并列分支。
4. **设置与团队目录**：`SettingsPage` 增加「剧本杀智能体」面板，`builtin-agent-prompts.ts` 登记指纹，`agent-team-catalog.ts` / `agent-team-profile-factory.ts` 增加 `workspaceType: "mystery"`。
5. **外部控制（MCP）**：`tool-routes.ts` 白名单与 `extras/external-control/skill/SKILL.md` 增量开放 `mystery` 读写与运行接口。

> **推荐协同顺序**：优先合入学术方案第 1 期（资料库自由标签与扁平绑定底座），剧本杀 worktree 在第 1 期专注独立 `mystery-store` 与智能体工具，待资料库底座合入 `main` 后直接复用统一的跨文体绑定组件。

## 3. 作品磁盘结构与数据模型

作品默认存放在 `<workspaceDirectory>/mystery-books/<projectFolder>/`，由 Core 独立注册表维护。

### 3.1 文件夹布局（内部稿与玩家稿物理分离）

```text
<projectFolder>/
├── deepwrite.json                   # 清单 kind: "deepwrite.mystery-book", schemaVersion: 1
├── AGENTS.md                        # 本作专属创作约定与文风约束
├── images/                          # （按需）搜证线索图、地图、插画资源（复用 book-images 规范）
├── truth/                           # 阶段 1：真相与核诡（上帝内部）
│   ├── overview.md                  # 盘面规格细则、世界观与变格/机制基础规则
│   ├── core-truth.md                # 故事真相、核诡/情感主轴/阵营规则、伪解答与排他锁凶链
│   ├── timeline-dispatch.md         # 全局时间线矩阵（时间×角色）+ 信息分流规划表
│   └── <extraDocId>.md              # （可选）补充上帝设定文档
├── characters/                      # 阶段 2：角色档案
│   ├── relations.md                 # NPC 设定与全局人物关系网（上帝内部）
│   ├── <roleId>.profile.md          # 单角色【上帝底牌】（真实身份、秘密、动机、防边缘位高光点）
│   └── <roleId>.pitch.md            # 单角色【公开选角页】（无剧透选角简介/心测词、说话腔调特征）
├── scripts/                         # 阶段 3：玩家人物本（角色 × 幕次 二维矩阵）
│   └── <roleId>/
│       ├── <actId>.brief.md         # 本幕【视角任务卡】（上帝内部：已知/目击碎片/隐瞒/任务/禁区/状态承接）
│       └── <actId>.body.md          # 本幕【人物本正文】（玩家可见：沉浸式叙事正文）
├── clues/                           # 阶段 4：搜证与公共物料
│   ├── public-openings.md           # 公共序幕导读、公开地图说明与公共小剧场（玩家可见）
│   ├── endings.md                   # 多分支结局演绎稿（DM 按场上结果宣读）
│   └── <roundId>.md                 # 单轮搜证线索卡面汇总（玩家可见：编号、归属地点、卡面图文描述）
└── dm/                              # 阶段 5：DM 主持手册（上帝内部）
    └── manual.md                    # 开本准备、分幕控场 SOP、线索投放逻辑说明、扶车 QA、完整复盘讲稿
```

### 3.2 清单核心契约（`deepwrite.json`）

```ts
export const MYSTERY_BOOK_GENRES = [
  "硬核推理",
  "情感沉浸",
  "机制阵营",
  "欢乐撕逼",
  "恐怖变格",
  "其他"
] as const;

export const MysteryNarrativePersonSchema = z.enum(["second", "first"]); // 默认 "second"（第二人称“你”）

export const MysteryBoardSpecSchema = z.object({
  playerCount: z.number().int().min(1).max(16), // 盘面规划目标提示，允许建设期与 roles.length 暂不一致
  actCountTarget: z.number().int().min(1).max(12), // 1 表示一本到底
  narrativePerson: MysteryNarrativePersonSchema,
  summary: z.string().max(2_000) // 性别配比、反串规则、侦探位/阵营胜负简述
});
```

清单包含：

- 基础与绑定字段：`id`、`title`、`genre`、`status`（`editing | completed`）、`boardSpec`、`linkedMaterialIds: CatalogId[]`、`linkedSkillIds: CatalogId[]`、`revision`、`createdAt`、`updatedAt`。
- 四个有序结构目录：
  - `truthDocuments`：内置 `overview`、`core_truth`、`timeline_dispatch` 三篇（内置项不可删，可新增自定义设定文档）；
  - `roles`：`{ id, name, tag, order }[]`，新建角色时原子创建 `.profile.md`、`.pitch.md` 及现有各幕的 `.brief.md` / `.body.md`；
  - `acts`：`{ id, title, order }[]`，新增幕次时原子补齐所有角色的该幕双文件；
  - `clueRounds`：`{ id, title, order }[]`，默认初始化 `第一轮搜证`、`第二轮搜证`。

> **不变量与可恢复性**：单作品内容项上限对齐 `CATALOG_PROJECT_MAX_CONTENT_ITEMS = 4_096`；至少保留 1 名角色与 1 幕；删除角色、幕次或轮次走可恢复还原点，运行占用时外部控制返回 `external.busy`。

## 4. 智能体与团队设计

### 4.1 系统提示词分层（对齐 [主要智能体系统提示词.md](主要智能体系统提示词.md)）

| 层级 | 可编辑 | 内容与职责 | 位置 |
| --- | --- | --- | --- |
| 1. 基础准则 | 否 | 身份、指令优先级、事实边界、回复语言（跟随 `promptLocale`） | `pi-runtime-adapter/src/prompts-base.ts` |
| 2. 剧本杀角色提示词 | **是** | 主创定位、五步建设链路（立项与角色 → 上帝真相与锁凶/体验闭环 → 时间线与视角任务卡拆解 → 分角受限执笔 → 线索池、DM 手册与防穿帮复核）、全题材质量标准。中英双语并在 `builtin-agent-prompts.ts` 登记指纹 | `contracts/src/agent-prompts/mystery.ts` |
| 3. 剧本杀工作区规则 | 否 | 轻量目录说明、稳定 ID 寻址、读写与检索用法、**视角隔离死线**（写 `body` 前必读对应角色卡与本幕 `brief`；严禁写出超出本幕 `brief` 知情边界的真相或他人心理；严禁在玩家可见文件中混入作者揭秘与分析） | `pi-runtime-adapter/src/mystery/prompts-rules.ts` |
| 4. 盘面人称硬约束 | 否 | 按当前作品 `boardSpec.narrativePerson` 强制人物本正文使用第二人称（“你”）或第一人称（“我”）沉浸叙事 | `pi-runtime-adapter/src/mystery/prompts-rules.ts` |
| 5. 写入审批与插图规则 | 否 | 自动保存或提案审批；编辑时保留已有 `images/` 本地插图引用 | `write-approval.ts`、`prompts-book-images.ts` |
| 6. 联网与管理工具 | 否 | 仅在本轮开启联网或资料库/团队管理工具时追加 | `web-search/prompt.ts` |

### 4.2 工具面与参数边界

遵循 [tool-args-validation.md](../error/tool-args-validation.md) 与 [limit-mismatch.md](../error/limit-mismatch.md)，Schema 仅做顶层扁平结构约束，字数与批量上限统一从 `@deepwrite/contracts` 导出并在 `execute` 内精确校验：

| 工具 | 作用与约束 |
| --- | --- |
| `read` | 按稳定 `kind` 读取：`board_spec`、`agents_md`、`truth_doc`、`character_relations`、`role`（`document = profile \| pitch`）、`player_act`（`role_id` + `act_id` + `document = brief \| body`）、`clue_round`、`public_doc`（`public_openings \| endings`）、`dm_manual`。支持全文读取（授予覆盖凭据）、`head` / `tail` 快速预览（用于看上一幕衔接，不授予覆盖凭据）及 `offset` / `limit` 分段读取 |
| `search` | 作品内跨五阶段全文关键词检索（支持限定阶段或只搜玩家可见稿），返回命中对象定位与上下文摘录，支撑 5～10 万字全本的时间点、道具、证词一致性核查 |
| `create` | 新建 `role`（支持按顺序批量创建）、`act`、`clue_round` 或自定义 `truth_doc` |
| `edit` | 修改 `board_spec`、结构 `meta`（重命名、排序）或文档内容（`content`、`append`、`insert`、`replacements`；覆盖已有非空内容前须已完整 `read` 并传 `overwrite_mode=replace_all`） |
| `delete` | 删除指定 `role`、`act`、`clue_round` 或自定义 `truth_doc`（保留至少 1 名角色与 1 幕） |
| 通用工具 | `query_linked_material_entries`、`load_skill`、`ask_user_question`（子智能体不提供）、`web_search` / `web_fetch`、`spawn_subagent` |

### 4.3 上下文预算与剪枝恢复

- **每轮固定上下文（轻量快照）**：仅注入作品标题、题材、盘面规格、`AGENTS.md`、五阶段目录树（含二维 `角色 × 幕次` 的 `[任务卡字数 / 正文字数]` 完成度矩阵、搜证轮次字数）及当前界面焦点定位，不预注入文档正文。
- **剪枝与摘要恢复**（`workspace-context-policy.ts` 的 `"mystery"` 策略）：
  - 超过工作预算 50% 时剪枝旧轮大段 `read` 结果与旧写入参数正文；
  - 触发检查点摘要后，自动补回本会话已加载技能（`skills`）、**当前焦点幕次的 `brief`（视角任务卡，防止长对话摘要后遗忘本幕视角禁区）**以及当前正在撰写的文档末尾 1,500 字。

### 4.4 内置「默认剧本杀团队」（默认均不勾选 `enabled: false`）

遵循仓库默认团队安全惯例，`parallelSubagents` 默认 `false`，内置 4 个职责正交的成员（初始均 `enabled: false`，由用户按需启用）：

| ID | 名称 | `agentMode` | `webSearchMode` | 职责与硬边界 |
| --- | --- | --- | --- | --- |
| `role_script_writer` | 分角代入执笔 | `pure-bare` + 按需抽卡 `auto` | `off` | **物理级防透视盲写。** 看不到 `truth/` 与其他角色剧本；仅根据主创在 `task` 中传入的「角色公开人设与口吻 + 本幕 `brief` 视角任务卡 + 上一幕状态摘要 + 人称/字数要求」撰写纯粹的玩家本草稿交回主创落盘，根除视角串戏与多角色同质化腔调。 |
| `clue_and_dm_builder` | 线索与控场编纂员 | `standard` | `off` | **专职物料与控场闭环。** 读取 `truth/` 与已确认的人物本，按信息分流表补齐各轮 `clue_round` 卡面、`public_openings`、`endings` 及 `dm_manual` 控场 SOP 与扶车 QA，不擅自改动核心真相与玩家本设定。 |
| `genre_core_advisor` | 核诡与体验顾问 | `pure-read` | `off` | **流派专项挑刺。** 纯只读不改稿；按作品题材审视硬核诡计排他性与伪解答、情感本各角色羁绊对等度（消灭边缘位）、或机制本阵营信息差与胜率平衡，输出具体漏洞与最小改动方案。 |
| `dm_playtest_auditor` | DM 测本审计员 | `pure-read` | `off` | **全本穿帮与断锤体检。** 结合 `search` 与按需 `read` 对照 `truth/` 审查全部玩家可见稿，输出四项分级清单：① 时空与交互目击撞车；② 超出本幕 `brief` 的视角越界泄密；③ 锁凶/破局必需碎片漏投（断锤）；④ 角色体量与任务参与度失衡。 |

启动 `standard` / `pure-read` 子智能体时，自动注入按已提交提案刷新后的实时剧本杀目录树、工作区规则与人称约束（`pure-read` 仅注入定位与读取规则；`pure-bare` 不注入全局目录以维持信息隔离）。

## 5. 工作台界面与无剧透分册导出

### 5.1 三栏工作台（遵循 [DESIGN.md](../DESIGN.md)）

- 剧本杀使用与短篇、剧本、长篇相同的创作空间。左侧公共目录管理作品选择、展开和文稿定位。中间对话与正文编辑器直接参与公共分栏，跟随全局布局顺序、折叠和宽度设置。
- 五阶段依次为「真相与统筹」「角色与选角」「分幕人物本」「线索与演绎」「主持人手册」。目录和输入框使用同一份阶段名称与图标。角色和幕次在目录中展开，作品菜单提供盘面、资料库、团队绑定和开本包导出。
- 公共对话面板提供作品与阶段切换。点选文引用会回到原句，点提案中的文件标题会打开对应的角色和幕次。提案在消息滚动区内审阅。
- `MysteryEditorPane` 向公共 `RightEditorPane` 提供文稿、搜索和版本操作。角色页可切换「上帝底牌」与「公开选角页」，分幕页可切换「视角任务卡」与「人物本正文」。可见性和叙事人称随当前文稿显示，人物本正文沿用剧本的排版偏好。
- 编辑和预览、撤销和还原、查找替换、大纲、字数、保存状态与其他作品遵循同一套交互。切稿前提交当前草稿，写入携带文稿版本号。并发修改时使用公共冲突对照窗口，作者可保留草稿、重载磁盘稿或确认覆盖已展示的版本。

### 5.2 无剧透分册导出（`.md` 与 `.docx`）

导出弹窗提供**格式选择**（`Markdown (.md)` 或复用 OOXML 打包器的 `Word (.docx)`，含标题层级、表格与 `images/` 插图输出）与**玩家本拆分方式**（`按角色合并成单本` 或 `按角色×幕次拆成独立文件`），按物理文件边界输出至 `<作品名>-开本包/`：

- `00-DM主持与真相手册`（汇总盘面、`truth/`、`relations`、全部角色 `.profile`、`endings` 与 `dm/manual`）
- `01-玩家选角简介（无剧透）`（仅汇总各角色 `.pitch` 与盘面公开信息）
- `02-玩家人物本/`（仅导出各角色 `.body`，**物理排除 `.brief` 与 `.profile`**）
- `03-搜证线索与公共物料/`（导出 `public-openings` 与各轮搜证卡面 `<轮次名>`）
