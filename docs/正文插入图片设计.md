# 正文插入图片设计

> 状态：一期代码已实现（2026-11-11）；验证范围与待验项见第 17 节。第 16 节为已定决策；实现时如需偏离，先改本文再改代码。

## 1 背景与目标

作者需要在正文里放插图（人物立绘、地图、分镜参考等），并在导出的 Word / EPUB 里带上这些图。现在正文是纯 Markdown，预览只渲染文字子集，导出也只写文字。

一期目标：

- 创作空间作品（短篇、剧本、长篇）里的**所有可编辑 Markdown 文档**——正文、设定、人物、世界观、剧情等——右键菜单新增“插入 ▸ 图片…”，选图后图片复制到**本书文件夹的 `images/`**，文档里插入一行 Markdown 图片引用。能力按“文档属于创作空间作品”在架构层统一开启，不按文档类型逐个接入（第 3 节第 11 项）。
- **编辑模式**仍是纯文本，显示 `![说明](images/xxx.png)` 原文。
- **预览模式**显示图片，并改造成**可直接编辑文字、实时渲染**的预览，不必为了改一个字切回编辑模式。
- **导出**：DOCX 与 EPUB 把图片写进导出文件；TXT 用文字占位（长篇按文件夹导出时另外复制用到的图片）。

一期不做：素材库、技能库插图；粘贴 / 拖拽插图；图片裁剪、缩放、对齐等排版参数；行内图片（与文字同一行）；智能体生成或插入图片；未引用图片的自动清理；长篇新增 DOCX / EPUB 导出；`images/` 双端同步；GIF。

## 3 关键决策

| # | 决策 | 理由 |
| --- | --- | --- |
| 1 | 图片存 `<作品文件夹>/images/`，短篇、剧本、长篇一致 | 随作品移动、备份、删除；与 `book-identity/` 同样不改 `deepwrite.json` schema |
| 2 | 正文里写**相对作品根目录**的路径 `images/<文件名>`，不按文档所在子目录计算 `../` | 正文文件在 `long/chapters/<hash>/` 等深层目录，按文件相对路径会随结构调整失效；固定前缀也便于校验。代价：外部 Markdown 编辑器打开深层文件时找不到图（见第 15 节） |
| 3 | 图片只认独占一行的 `![说明](images/…)` | 小说插图都是块级；行内图片会让段落渲染、字数统计、导出分段都变复杂 |
| 4 | Core 是 `images/` 唯一写入者；Main 选文件、读字节、校验、转码；WebP 在 Main 管理的临时沙盒窗口内用 Chromium 解码为 PNG，应用 Renderer 拿不到本机路径 | 沿用“Core 唯一写入者”“Renderer 不碰 `node:`”的边界 |
| 5 | 显示走新的只读协议 `deepwrite-book-image:`，不复用 `deepwrite-cover:` | 两者解析的子树、大小上限和缓存策略不同，分开更容易做白名单校验 |
| 6 | 预览改为**真正的所见即所得编辑**：结构化文档模型同时驱动渲染和编辑，点击只放置光标，不切换到源码输入框 | 使用按需加载的 ProseMirror 文档模型与 Markdown 解析、序列化；未修改的块保留原始源码。存储仍为 Markdown，所有编辑进入现有 `content` 与撤销历史，自动保存、冲突检测、提案、“运行中可编辑正文”的规则全部复用 |
| 7 | 插入不替换选区，插在选区末尾所在行之后 | 避免误删正文；插入可用 Ctrl+Z 撤销 |
| 8 | 撤销插入、删除引用都**不删图片文件** | 撤销 / 重做、版本历史、提案拒绝都可能把引用找回来；孤儿图片清理留到后续 |
| 9 | WebP 在插入时由 Main 转成 PNG 保存；PNG、JPEG 原样保存 | DOCX 对 WebP 兼容性差；`nativeImage` 在部分平台不能解码 WebP，改由 Main 管理的临时沙盒 Chromium 窗口解码、校验尺寸并转 PNG；窗口只收图片字节，无 Preload、Node 或网络权限，完成或失败后销毁。PNG / JPEG 沿用 `nativeImage` 校验；存下来的格式两种导出都能直接用 |
| 10 | 导出遇到缺失图片不失败：跳过并在结果中计数，界面 toast 提示 | 一张图丢了不该挡住整本导出 |
| 11 | 插图能力按**作品域**开启：工作区模块向编辑器提供一个 `BookImageContext`（作品引用）；有上下文且文档可编辑就能插入，有上下文就能显示。不在任何地方按“正文 / 设定 / 人物”判断 | 存储、协议、渲染、插入对所有文档完全相同，按文档类型逐个开放只会多出分支和遗漏。素材库、技能库没有作品上下文，自然不支持；以后新增的作品文档类型自动获得能力 |

## 4 存储与引用格式

### 4.1 目录与文件名

```
<作品文件夹>/
  deepwrite.json
  images/
    海边日落-3f9a1c2e.png
    地图-a07b5d11.jpg
  ……（原有正文、设定、long/ 等）
```

- 文件名 = 原文件名主干（将 `<>:"/\|?*`、控制字符、空白、`)`、`]` 规整为短横线，连续点也规整为短横线；去掉首尾空格、点与短横线，最多 40 个字符，空则用 `image`）+ `-` + 8 位随机十六进制 + 扩展名（`.png` / `.jpg`）。随机段保证不覆盖，不用于去重。
- Core 以独占创建（`wx`）原子写入，目录不存在时创建；拒绝符号链接，`images/` 本身是符号链接时报错。
- 单张 ≤ 20 MB，长边 ≤ 8192 px；一次最多选 10 张。

### 4.2 正文引用

```markdown
上一段正文。

![海边日落](images/海边日落-3f9a1c2e.png)

下一段正文。
```

- 识别规则（contracts 导出，Renderer 与 Main 共用）：整行去首尾空白后匹配 `^!\[([^\]\n]{0,200})\]\((images/[^/\\\s)]{1,120}\.(?:png|jpe?g))\)$`。
- 说明文字默认取原文件名主干，可在编辑模式或预览中直接改。说明为空时预览与导出都不显示图注。
- 不匹配的写法（外链、绝对路径、`../`、行内图片）一律按普通文字处理，不发起任何加载。

## 5 进程与数据流

### 5.1 插入

```
Renderer 右键 ──登记 insertImage 扩展（记下文档 id、内容快照、插入偏移）
Main 原生菜单 ──“插入 ▸ 图片…”──► Renderer 扩展回调
Renderer ──bookImages.pick { book }──► Main
Main  showOpenDialog（png/jpg/jpeg/webp，多选）
      O_NOFOLLOW 只读打开 → 大小、文件头、解码、尺寸校验 → WebP 经 Main 临时沙盒 Chromium 窗口转 PNG
      ──bookImages.write { book, images:[{bytes, ext, baseName}] }──► Core
Core  resolveProject(book) → images/ 独占原子写入 → 返回 [{ path, alt }]
Main ──{ status:"saved", images, rejected }──► Renderer
Renderer 校验文档仍是同一篇且内容未变 → 走编辑器的 applyEdit 插入引用（进入撤销历史）
```

- `resolveProject` 复用 `book-identity/commands.ts` 里按作品类型解析目录的逻辑（抽成共用函数，不复制一份）。
- 文件对话框是窗口模态，期间用户无法输入；内容快照仍要比对，防止外部同步或重载在此期间换了文档。不一致时不插入，toast：“图片已保存到本书 images 文件夹，但文档已变化，未插入引用。”
- 部分文件被拒（格式、大小、尺寸）时，已通过的照常插入，被拒的逐个列在 toast 里。错误按 `ErrorPayload.code` 分支，不靠错误文字。

### 5.2 显示

- URL：`deepwrite-book-image://asset/<projectType>/<projectId>/<文件名>`，Renderer 由引用路径和当前作品拼出，不含本机路径。
- Main 协议处理器沿用 `cover-protocol.ts` 的校验方式（只允许 GET、host 为 `asset`、拒绝 `..` 与编码斜杠、无 query / hash），经 Core `bookImages.resolve` 取得绝对路径、MIME、字节数；Core 校验文件在 `<作品>/images/` 下、是普通文件、不是符号链接。Main 以 `O_NOFOLLOW` 打开并流式返回，并发上限 8。
- `index.html` CSP 的 `img-src` 增加 `deepwrite-book-image:`。
- 图片加载失败（缺失、损坏）时显示占位块：“找不到图片 images/xxx.png”，不抛错、不打断预览。

### 5.3 导出

见第 10 节。Main 收到导出请求后，按作品引用经 Core 解析图片路径，自行只读读取字节，写入导出文件。

## 7 右键菜单

- Main `buildTextMenuItems`：`context.canInsertImage` 为真时，在菜单末尾（“全选”之后）加分隔线和子菜单“插入 ▸ 图片…”。用子菜单是为以后加“分隔线”“场景切换”等插入项留位置，一期只有一项。
- 文案：`insert: "插入"`、`insertImage: "图片…"`（en-US：`Insert` / `Image…`），写入 `main/native-messages/`。
- Renderer `TextMenuExtension` 增加可选 `insertImage?: () => void`；`actionAllowed` 对 `insertImage` 只看扩展是否提供。
- **预览区的右键**：所见即所得正文为可编辑元素，提供剪切、复制、粘贴、全选与共享撤销 / 重做；有选区时保留“插入输入框”。登记了 `insertImage` 扩展的图片或空白区域也能打开插入菜单；只读文档遵守原有复制规则。
- 哪些地方登记 `insertImage`：只看两个条件——编辑器拿到了 `BookImageContext`，且当前文档可编辑（与 textarea 的 `readonly` 同一判断）。因此创作空间里经 `RightEditorPane`、`LongWorkspaceEditor`、`LongManuscriptEditor` 编辑的全部文档都可插图，包括短篇 / 剧本的小节、剧集、角色状态文件和各类设定，长篇的章节、人物、世界观、剧情与概览。素材库、技能库没有上下文，不登记；只读、被锁时不登记。
- 插入位置：
  - 编辑模式：取 `selectionEnd` 所在行的行尾，插入 `\n\n![说明](images/…)\n\n`，再规整掉多余空行（前后最多保留一个空行）。
  - 预览模式：将结构化文档选区映射到 Markdown，取光标所在行的行尾插入；内核尚未就绪时回退到右键所在块的 `data-src-end`，空白处回退到文末。
  - 多张图按选择顺序连续插入，每张独占一段。

## 8 编辑模式

不改 textarea 的任何行为，只多了右键插入。图片引用就是普通文字，可查找替换、可手改说明和路径。

## 9 预览模式改造：所见即所得编辑（2026-11-12 修正）

此前“点击块切回源码”的架构不能满足用户要求，停止沿用这套编辑模型。

- 预览使用 ProseMirror 的结构化文档模型。标题、粗体、删除线、引用、列表、代码块、表格与图片在显示与编辑时使用同一份节点；点击仅移动光标，不替换节点、不显示 Markdown 标记，不新增编辑框。
- Markdown 是持久化格式，经明确的 parser / serializer 与结构化文档转换；不从任意 HTML 反推正文。不变的顶层块保留其原始 Markdown，修改的块按支持的语义序列化。
- 编辑器内核在预览挂载后按需加载，避免把富文本依赖加入工作台启动静态依赖图。依赖版本由 workspace catalog 管理。
- 中文输入法组合期间仅更新编辑器内部文档，不向自动保存或历史提交候选文本；组合结束提交一次。复用父编辑器的保存、冲突检测、脏标记和有界撤销历史。
- 普通回车、删除、选区替换由编辑模型处理，保留未删除文字的格式；只读和锁定时禁用编辑。撤销 / 重做不切换为源码编辑模式。
- 新段落行首输入 1–6 个 `#` 后按空格，直接转成对应级别标题并移除标记；保存为标准标题 Markdown，不将其当成普通文字添加反斜杠。代码块、行内代码、行中井号与表格单元格保持原义；刚转换后可按退格恢复普通文字。
- 图片仅接受独占一行且符合 `parseBookImageLine` 的作品根目录相对路径，通过已有只读协议加载；图片不显示文件名或图注，点击不展示引用源码，删除只移除引用。
- 末尾图片后保留空白光标位置，只用于编辑，不额外写入 Markdown；插图完成后恢复预览光标。光标在图片后一行开头时按退格可删除前图，点击图片显示细选中线，按 Delete 可删除；删除和撤销保持在预览中。
- 支持的表格单元格、列表项和格式化文字均能直接修改。粘贴不能导入外部图片、脚本或任意 HTML 权限。
- 查找快捷键、选区引用、右键插入图片接回父编辑器原有功能；大纲节点保留 `data-markdown-heading-index`。

验收必须使用含标题、粗体、列表、表格及图片的真实文档：点击前后 DOM 节点和样式不变，文字修改后结构与持久化 Markdown 格式保留；不能仅用普通段落无边框的截图或样式断言代替。

## 10 导出

### 10.1 共同规则

- Main 逐行用 `parseBookImageLine` 识别图片行；同一图片多次引用只打包一份。
- 读取：经 Core `bookImages.resolve` 拿路径，Main 以 `O_NOFOLLOW` 只读读取，校验大小与文件头；失败的计入 `missingImages` 并跳过该行。
- 单次导出图片总量上限 512 MB，超出时报 `book_image.export_too_large`，不写半成品。
- 其他 Markdown 符号的导出行为不在本次范围内，保持现状。

### 10.2 DOCX

- 图片写入 `word/media/image<N>.png|jpg`；`[Content_Types].xml` 加 `png` / `jpeg` 的 `Default`；`document.xml.rels` 为每张图加 `image` 关系。
- 图片自成一个居中段落（不带首行缩进），用 `<w:drawing><wp:inline>`；尺寸按像素 × 9525 EMU（96 dpi），宽度超过版心（A4 去左右边距，约 5,731,510 EMU）时等比缩到版心宽。像素尺寸用 `nativeImage.getSize()` 读取。
- `wp:docPr` 的 `descr` 写说明文字；说明非空时紧跟一个居中的图注段落（小一号字）。
- `document.xml` 需补 `wp`、`a`、`pic`、`r` 命名空间声明。

### 10.3 EPUB

- 图片放 `OEBPS/images/<N>.png|jpg`，在 `content.opf` 的 manifest 登记（`image/png` / `image/jpeg`，均为 EPUB 核心媒体类型）。
- 正文中输出 `<figure><img src="images/<N>.png" alt="说明"/><figcaption>说明</figcaption></figure>`；`styles.css` 增加 `figure{margin:1em 0;text-align:center;text-indent:0}img{max-width:100%;height:auto}figcaption{font-size:.9em}`。
- 原先按空行分块成 `<p>` 的逻辑改为：块内遇到图片行先结束当前段落，再输出 figure。

### 10.4 TXT

- 图片行替换为 `[图片：说明]`，说明为空时为 `[图片]`。短篇 TXT 不导出图片文件。
- 长篇导出（世界观、人物、剧情、正文各分区同样处理）：单个 TXT 只占位；文件夹模式在导出目录下建 `images/`，把用到的图片按原文件名复制进去，占位改为 `[图片：说明](images/原文件名)`，便于对照。长篇一期不新增 DOCX / EPUB。

### 10.5 导出界面

- 短篇导出弹窗的格式说明补一句：“DOCX、EPUB 会包含文中的图片；TXT 以文字占位。”长篇导出弹窗补：“图片以文字占位；按文件夹导出时，用到的图片会复制到导出目录的 images 文件夹。”

## 15 风险

- **预览编辑的光标映射**是最容易出体验问题的地方：带格式的段落映射可能偏一两个字。一期只保证纯文字段落精确，其余块落到行尾，先在实机上看反馈。
- **长章节重绘性能**：每次输入都重新拆块。块 html 按源码缓存，只重新生成变化的块；若实测仍卡，再改为只重拆受影响的相邻块。
- **外部编辑器兼容**：根目录相对路径在深层文件里不被 Typora 等识别（第 3 节第 2 项）。
- **孤儿图片**会随时间积累，需要后续提供“清理未引用的图片”。

## 16 已定决策（2026-11-11 用户确认）

1. **长篇导出**：一期不新增 DOCX / EPUB。TXT 中图片行换成 `[图片：说明]`；文件夹模式另外复制用到的图片到导出目录 `images/`（第 10.4 节）。
2. **可插图的文档范围**：创作空间作品的**全部**可编辑 Markdown 文档，按作品上下文在架构层统一开启，不按文档类型区分（第 3 节第 11 项、第 7 节、第 9.3 节）。素材库、技能库不支持。
3. **双端同步**：一期 `images/` 不同步，手机端显示引用原文；二进制同步与手机端渲染以后单独立项。
4. **格式范围**：PNG / JPEG / WebP（WebP 转 PNG 存储），不支持 GIF。
