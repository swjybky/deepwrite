# 文件版本管理功能设计

> 状态：M0–M4 功能实现完成，M5 自动化验收与人工待验项见第 13 节（2026-11-11）。版本记录默认关闭，由用户自行开启。实现时如需偏离本文，先改本文再改代码。

## 1 背景与目标

智能体在对话中会直接改写正文和设定。自动审批模式下改动立即落盘，现有的“撤销这次修改”只针对单张提案、且只在对话卡片上可用；过了几轮对话后，用户想回到某一轮之前的样子，目前没有入口。

目标：

1. 每一轮对话中被修改的文件，各自保存一个版本。
2. 编辑器工具栏“替换”按钮右侧新增“版本”图标，点开后列出该文件的版本记录，可逐个切换查看、看与上一版的差异，并回退到任一版本。
3. 版本只为“修改”而建：创建、删除操作本身不产生版本；从文件第一次写入文本起算第一版。
4. 版本数据只存在本机，不进入双端同步。
5. 设置 → 常规 新增“版本控制”分组，一个开关控制开启/关闭。

不做（一期）：

- 手动编辑的独立版本（手动内容只在对话修改前被补存一次，见 3.1）。
- 素材库、技能库条目的版本。
- “整轮对话一键回退所有文件”（一期按文件逐个回退）。
- 版本命名、备注、手动打版本、清空版本记录。
- 手机端（deepwrite-app）查看版本。

## 2 需求确认记录

| 问题 | 结论（2026-11-11 用户确认） |
| --- | --- |
| 手动编辑是否算版本 | 只在对话修改时建版本；若对话改动前文件里有尚未入版本的文字（手写的或首次写入），先把改动前内容补存为“对话前”版本。这样第一版就是文件第一次有文字时的内容，并且永远能回到智能体动手之前 |
| “只记录修改的内容” | 只给“修改”建版本，创建、删除不建；每个版本存完整文本（gzip 压缩），查看时现算与上一版的差异 |
| 覆盖范围 | 作品内全部文本：短篇/剧本的正文与设定文档、长篇的章节正文与人物/世界观/剧情等设定文件。素材库、技能库不在内 |

## 3 关键决定

| # | 决定 | 理由 |
| --- | --- | --- |
| 1 | “一轮对话”= 一次运行（`runId`）。同一轮对同一文件的多次写入合并成一个版本，内容取该轮最后一次写入 | 与需求“每一次对话中修改的文件进行一次版本保存”一致；并行子智能体同轮写同一文件也只占一个版本 |
| 2 | 版本在 **Core 落盘时**截获，而不是运行结束后由界面补记 | Core 写入时手里同时有改前、改后文本，不依赖界面是否开着；崩溃也不会漏掉“改前”内容 |
| 3 | 只有带 `versionOrigin`（会话 + 运行标识）的写入才建版本 | 手动保存、外部 MCP 直接写入、同步拉取、拆书导入都不带，天然排除；不用在 Core 里猜写入来源 |
| 4 | 开关由 Main 权威把关：关闭时 Main 剥掉写入命令里的 `versionOrigin`，并拒绝 `versions.*` 命令 | Renderer 不是可信判定方；Main 本来就持有常规设置 |
| 5 | 按文档 ID 建历史（短篇 `documentId`，长篇 `fileId`），不按路径 | 改标题、长篇按书名改文件夹都不会丢历史 |
| 6 | 回退 = 把旧版内容写回当前文件，并新增一个“回退”版本；历史不删除 | 回退本身可再回退；回退前若有未入版本的手动修改，先补存，不丢字 |
| 7 | 版本存在作品文件夹 `.deepwrite/versions/` 下 | 双端同步已跳过所有 `.` 开头的目录（`device-sync-files.ts` 的 `readDeviceSyncFiles`、contracts `safeSyncFile`），无需新增同步规则；作品移动、数据目录迁移时历史随作品走 |
| 8 | 版本保存失败不影响正文保存，只记日志 | 与长篇还原点“快照失败只丢撤销，不丢保存”的既有原则一致；下一次截获会自动补齐（见 3.1 规则②） |
| 9 | 每个文件最多保留 100 个版本，超出删最旧的 | 与长篇还原点保留数一致；完整文本 gzip 后单章约十几 KB，100 版可接受 |
| 10 | 开关默认 **关闭**（2026-11-11 用户最新要求） | 由用户自行在设置中开启后开始记录版本 |

### 3.1 版本截获规则

Core 每处理一次带 `versionOrigin`（运行 R）的文件写入，拿到改前文本 `before`、改后文本 `after`，对该文件历史执行：

```
latest = 该文件最新一个版本（可能没有）

① 补存对话前内容：
   若 before 非空，且（latest 不存在 或 before ≠ latest.content）
   → 追加版本 { kind: "pre_conversation", content: before }
   → latest = 这个新版本

② after 为空 → 结束（不存空版本；清空前的内容已在 latest 里）
③ after = latest.content → 结束（内容没变，不建版本）
④ 若 latest.kind = "conversation" 且 latest.runId = R
   → 原地更新 latest 的内容与时间（同一轮合并为一个版本）
   否则 → 追加版本 { kind: "conversation", runId: R, content: after }
```

由此得到的行为：

| 场景 | 结果 |
| --- | --- |
| 新建空文件，智能体首次写入 | v1 对话修改 |
| 智能体新建文件时直接带正文（长篇 `documentWrites` 的 `create` 模式、短篇“建小节 + 写正文”） | v1 对话修改（创建动作本身不算版本，第一次写入的文字算第一版） |
| 用户先手写，智能体再改 | v1 对话前（手写内容）、v2 对话修改 |
| 同一轮改同一文件 3 次 | 仍只有 1 个对话版本，内容为第 3 次 |
| 同一轮两次写入之间用户手动改过 | 对话前（手动内容）+ 本轮第二个对话版本。不丢用户的字 |
| 两轮对话各改一次 | 2 个对话版本 |
| 智能体写入内容与最新版一致 | 不新增 |
| 智能体清空文件 | 不新增空版本；清空前的内容已是最新版，可回退 |
| 删除文件 | 不建版本；历史保留在磁盘，文件从回收站恢复（同 ID）后历史仍在 |
| 手动保存、MCP 直接写入、同步拉取 | 不建版本；下次对话改动该文件时由规则①补存 |
| 开关关闭期间的对话修改 | 不建版本；重新开启后下次对话改动时由规则①补存当时内容 |
| 版本保存失败（磁盘错误、进程崩溃在主事务之后） | 正文照常保存；下次截获时 before ≠ latest，规则①自动补上 |

回退（用户在版本面板操作）走同一套规则：先以当前磁盘内容为 `before` 执行规则①（kind 记为 `pre_conversation`，界面文案“回退前内容”），写回旧版内容后追加 `{ kind: "restore", restoredFromSeq: N }`。

## 4 交互设计

### 4.1 版本图标

- 位置：`EditorTextTools.vue` 中“替换”按钮右侧、“一键规范格式”左侧。图标用已有的 `history`，尺寸、样式与相邻 `.text-tool-button` 一致。
- 文案：`aria-label`“版本记录”，`title`“版本记录”。
- 显示条件（同时满足）：
  1. 设置“保存对话修改的版本”已开启；
  2. 当前打开的是作品文本：短篇/剧本的 `RightEditorPane`（素材库、技能库条目不显示），或长篇 `LongWorkspaceEditor` 两处工具栏中当前文件为 Markdown 文本的情况（伏笔视图、剧情线视图本来就不显示文本工具，不变）。
- 没有任何版本时也显示，点开后显示空状态。

### 4.2 版本面板（弹窗）

点击图标打开居中弹窗，宽 `min(880px, 100vw - 48px)`，遵循 [design/dialogs.md](../design/dialogs.md) 三段式。

```
┌ 版本记录 · 第三章 ─────────────────────────────────────────────── ✕ ┐
│ ┌ 版本列表（260px，自身滚动）┐ ┌ 内容区 ──────────────────────────┐ │
│ │ ● 当前内容                 │ │ [与上一版对比] [完整内容]          │ │
│ │   有尚未入版本的修改        │ │                                    │ │
│ │ ─────────────────────────  │ │ @@ -12,4 +12,9 @@                 │ │
│ │ v4 对话修改   今天 14:32    │ │ 12 12  林晚，二十三岁……            │ │
│ │   “把第三章打斗改紧凑…”    │ │    13 + ……                         │ │
│ │   +312 字                  │ │                                    │ │
│ │ v3 回退（回到 v1） 13:05    │ │                                    │ │
│ │ v2 对话修改   昨天 22:10    │ │                                    │ │
│ │ v1 对话前内容 昨天 22:09    │ │                                    │ │
│ └────────────────────────────┘ └────────────────────────────────────┘ │
│ 版本只保存在本机，不参与双端同步。           [关闭] [回退到此版本]    │
└──────────────────────────────────────────────────────────────────────┘
```

- **列表**：新到旧排列。首行固定为“当前内容”（不是版本）；当前内容与最新版本不同时，副标题写“有尚未入版本的修改”。每个版本一行：版本号、类型（对话修改 / 对话前内容 / 回退前内容 / 回退（回到 vN））、时间、来源（对话版本显示该轮用户消息首行摘要，最多 1 行省略）、字数变化（与上一版的字符数差，Core 只存字符数，列表不现算差异）。
- **内容区**：两个分段按钮。“与上一版对比”用现有 `buildAgentTextDiff` + 差异组件（与提案卡片同一套视觉）；v1 或“当前内容”与最新版对比。“完整内容”只读展示该版本全文。内容按需读取，切换版本时只读选中版本和它的上一版。没有历史版本时显示“暂无历史版本，无法对比当前内容。”，不得把当前全文与空文本比较；比较所需版本尚未读取成功或读取失败时，也不生成差异，读取失败沿用不可用提示。单行插入只标记实际新增行，其后未变内容保持上下文。
- **回退**：选中某版本后启用“回退到此版本”（选中“当前内容”或最新版且当前未改动时禁用）。点击后弹二级确认：标题“回退到 v2？”，说明“当前内容会先保存为一个版本，回退后仍可再回到现在的样子。”主按钮“回退”。成功后关闭确认，列表刷新并选中新的“回退”版本，编辑器内容刷新，toast“已回退到 v2”。若正文回退成功但版本保存失败，返回 `version: null`，仍刷新编辑器，列表选择“当前内容”；不虚构未落盘的版本，遵循版本失败不影响正文的原则。
- **禁用回退的情况**（按钮禁用 + 悬停说明）：该作品有智能体运行中；当前文件为只读内容（仍可查看版本）；编辑器有未保存内容且自动保存关闭（自动保存开启时先等当前保存完成再回退）。
- **错误**（按 `ErrorPayload.code` 分支，走 toast，弹窗高度不变）：
  - `version.conflict`：当前内容在打开面板后被改过 → “内容刚刚变化过，已刷新版本列表，请重新确认”；自动刷新列表。
  - `version.unavailable`：版本文件缺失或损坏 → “这个版本的记录已损坏或不存在”。
  - `version.busy`：运行中 → “智能体正在修改这部作品，请等运行结束后再回退”。
  - `version.disabled`：设置已关闭 → 关闭弹窗。

## 5 数据与存储

### 5.1 位置与格式

```
<作品文件夹>/.deepwrite/versions/
  <key>/                    key = sha256("catalog:<documentId>" 或 "long:<fileId>") 前 32 位十六进制
    index.json              版本元数据
    v<seq>-<random8>.md.gz  每个版本一份完整文本（UTF-8，gzip）
```

`index.json`：

```json
{
  "schemaVersion": 1,
  "target": { "workspace": "long", "bookId": "...", "fileId": "..." },
  "nextSeq": 5,
  "versions": [
    {
      "id": "v4-1a2b3c4d",
      "seq": 4,
      "kind": "conversation",
      "createdAt": "2026-11-11T06:32:10.000Z",
      "updatedAt": "2026-11-11T06:33:02.000Z",
      "origin": { "sessionId": "...", "runId": "...", "summary": "把第三章打斗改紧凑…" },
      "sha256": "...",
      "charCount": 5321
    }
  ]
}
```

- `kind`：`pre_conversation` | `conversation` | `restore`；`restore` 额外带 `restoredFromSeq`。回退前补存的版本复用 `pre_conversation`，带 `reason: "restore"` 以便界面显示“回退前内容”。
- 版本号 `seq` 单调递增，删除旧版本不重排，界面显示的 vN 不会变。
- 单个版本大小上限与该文档写入上限共用（短篇 `maxMarkdownBytes`，长篇 `LongWriteDocumentInputSchema` 的 16 MiB），超限只跳过版本、不影响保存；读取版本使用同一上限（AGENTS.md“同一份数据的读写上限”）。

### 5.2 写入顺序与原子性

1. 主事务（正文写入）提交成功。
2. 仍在同一把写锁内：先写新的 `.md.gz`（新文件、durable 写入），再以临时文件 + rename 原子替换 `index.json`。“原地更新”时写新内容文件、改索引指向，再删旧内容文件。
3. 索引替换成功后修剪：超出 100 个的旧版本从索引移除并删除其内容文件；目录里不被索引引用的 `.md.gz`（上次中断留下的）一并删除。

`index.json` 损坏（解析失败或 `target` 不符）时：改名为 `index.corrupt-<时间>.json` 保留现场，按“无历史”继续（下一次截获由规则①补存当前内容）。`.corrupt-` 已在 `safeSyncFile` 排除列表中。

### 5.3 不进入双端同步与其他出口

| 出口 | 现状 | 本功能处理 |
| --- | --- | --- |
| 双端同步上传 | `readDeviceSyncFiles` 跳过 `.` 开头的目录；`safeSyncFile` 拒绝路径含 `.` 开头片段 | 不改代码，补测试锁定 |
| 双端同步拉取写入 | 只写清单内文件 | 不带 `versionOrigin`，不建版本 |
| 外部控制（MCP） | 读写工具只收 `workId` / `documentId`（`external-control/read-tools.ts`、`write-tools.ts`），不接受任意路径，版本目录不可达；直接写入不带 `versionOrigin` | 不改；一期不开放版本相关 MCP 工具 |
| 云备份 | `cloud-backup/catalog-reader.ts` 只跳过 `.DS_Store` 等，**会带上 `.deepwrite/`** | 跳过 `.deepwrite/versions`（已确认）：`collectProjectFiles` 遍历时排除该目录，其余 `.deepwrite/` 内容维持现状 |
| 复制作品 | 短篇按清单重建，不复制内部目录 | 复制件不带历史；长篇复制实现时核对 |
| 用户数据目录迁移 | 整个作品文件夹搬迁 | 历史随作品走，符合预期 |

## 8 边界情况

| 情况 | 处理 |
| --- | --- |
| 运行中用户边写边被智能体改（“运行中可编辑正文”） | 规则①在每次智能体写入前补存手动内容，不丢字 |
| 回退时编辑器里有未保存输入 | 自动保存开启：先等当前保存落盘再发回退；关闭：回退按钮禁用并提示先保存 |
| 回退后编辑器 | 按“外部写入刷新”的既有路径刷新当前文档内容；该文档的编辑器撤销栈清空（避免撤销到回退前的旧文本又覆盖） |
| 回退目标与当前内容相同 | 按钮禁用 |
| 文件已删除 | 编辑器打不开该文件，没有入口；历史保留 |
| 作品整体删除 | 历史随作品文件夹一起进回收站或删除 |
| 非 UTF-8 / 超大文件 | 跳过版本，记日志，不影响保存 |
| Windows 路径 | key 用十六进制哈希，不含路径字符；所有拼接用 `node:path`，测试在 Windows CI 跑 |

## 11 风险

- **语言资源体积预算**：多个会话都在加文案，预算余量很小。新增文案控制在约 30 条以内，开工前先量当前体积；用户已于 2026-11-11 批准从 840,000 B 小幅提高到 845,000 B，新增文案仍保持精简。
- **大文件行数**：`RightEditorPane.vue`（925 行）、`LongWorkspaceEditor.vue`（3487 行）已远超建议上限，本功能只在其中加显示条件和事件转发，逻辑全部放进新组件与 composable；不碰 `WorkspaceShell.vue`。
- **写入调用处多**：漏接一处会导致那类提案不建版本（但下次会被规则①补成“对话前”，不丢内容）。P1 测试按调用处逐一覆盖。
- **磁盘占用**：长篇章节多且频繁改写时版本目录会变大。一期靠每文件 100 版上限；若用户反馈，再加按作品总量上限或“清空版本记录”。
