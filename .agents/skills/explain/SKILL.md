# 讲解代码与设计

讲之前先读，不凭印象。没读到的代码不讲，没找到依据的原因不猜。

## 先查依据

1. **找到代码。** 先在 `references/features/README.md` 找到对应功能页，按页里的「前后端对应」定位文件，再读实际代码（入口、调用链、数据落在哪）。
2. **查历史。**
   - `git log --follow -p -- <文件>` 看这个文件怎么演变来的。
   - `git log -S '<关键名字>' --oneline` 找引入或改动某段代码的提交。
   - `git blame -L <起>,<止> <文件>` 找具体几行的来历，再 `git show <提交>` 看当时一起改了什么。
3. **查说明。** 代码注释、`AGENTS.md` 里的边界约定、提交信息。
4. **需要时跑起来看。** 用验证 CLI（`pnpm -s ctl`）在隔离测试实例上操作一遍，确认讲的行为是真的。

## 讲两部分

### 怎么运行

- 从用户能看到的入口讲起（点了哪里、调了哪个命令），按调用顺序讲到数据落盘或结果返回。
- 每一步标出文件和位置，写成可点击的 `路径:行号`。
- 用大白话，少用术语；必须用的术语第一次出现时解释一句。

### 为什么这么写

- 每条“为什么”都注明依据：哪个提交、哪条注释、哪份文档、哪条约定。
- 找不到依据的，写明“没有找到记录”，可以给出推测，但要标为推测，并说明推测的理由。
- 发现代码和文档对不上时，以代码为准，并指出不一致的地方。

## 最后

列出读过的文件和查过的提交，方便用户自己核对。
