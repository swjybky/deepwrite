# 经验提炼与剧本沉淀（ccs-distill）

## 触发条件

满足任一条件时使用本技能：

- 完成一次配合顺畅、质量过硬的合作，需要把可复用的流程或验收要点沉淀下来。
- 遇到一次用户明确纠正（如指出门禁放过了真实问题、文案或控件规范漏检、调查方式走偏），需要固化到工作流。
- 在历史记录（`test/`、`notes/handoff/`、`git log`）中看到多次独立出现的有效做法。
- 刚用 [ccs-mode](../ccs-mode/SKILL.md) 走通一次真实任务，而对应剧本目前仍是占位文件（如 `investigate.md`、`prototype.md`）。

**失败分流红线**：若在梳理历史记录或复盘时发现**反复踩坑、同一类返工或执行失败**，不要在本技能里硬加文字补丁，直接转交 [ccs-retro](../ccs-retro/SKILL.md) 做失败诊断。

## 步骤与完成标准

1. **采集候选并核对证据**
   - 每条候选必须写齐四个要素，缺原始证据不入库：

   | 要素 | 填写要求 |
   | --- | --- |
   | **适用情形** | 哪类任务、哪个阶段或什么触发条件下适用 |
   | **具体做法** | 可执行的动作、命令、核查清单或输出结构 |
   | **有效原因** | 它解决了什么盲区、为什么能防错或提效 |
   | **原始证据** | 用户原话、`test/<日期-主题>/` 报告/截图/指标 JSON、测试结果、`ctl` 输出或 `git` 提交 |

   - 同时核对仓库已有能力（`tools/control/`、`rules/README.md`、`AGENTS.md`、`DESIGN.md`、`design/*.md`、`references/features/`、`.agents/skills/`），剔除已经覆盖的项；发现反复失败的坑，转交 [ccs-retro](../ccs-retro/SKILL.md)。
   - **完成标准**：输出候选清单，每条四要素齐全且均能回指仓库文件、记录或用户原话；已做去重与失败分流。

2. **按落点优先级判定归属**
   - 与 [ccs-retro](../ccs-retro/SKILL.md) 共用同一落点优先级——先往现有自动工具、规则和文档放，再考虑剧本；只有足够独立且无法并入时才新建：

   | 优先级 | 落点 | 判定条件 | 对应位置 |
   | --- | --- | --- | --- |
   | 1 | **现有工具** | 可由脚本或命令稳定执行、采集或核验 | `tools/control/`、`tools/check-*.mjs` |
   | 2 | **自动规则** | 可机械判定对错的源码、文案、结构或契约约束 | `tools/eslint-rules.mjs`、`tools/control/lib/repo-rules.mjs`、`rules/README.md` |
   | 3 | **现有文档或规范** | 跨任务通用的产品边界、界面/文案审查、功能入口与操作说明 | `DESIGN.md`、`design/*.md`、`references/features/*.md`、`AGENTS.md` |
   | 4 | **更新已有剧本** | 经验只是现有某类任务中的一步；跨多类任务的共同步骤写入 `ccs-mode` 共守条款 | `.agents/skills/ccs-mode/playbooks/<已有剧本>.md` 或 `ccs-mode/SKILL.md`「所有剧本共同遵守」 |
   | 5 | **补全占位剧本** | 对应占位剧本已存在（如 `investigate.md`、`prototype.md`）且真实任务证据足够 | `.agents/skills/ccs-mode/playbooks/<占位剧本>.md` |
   | 6 | **新建剧本或技能** | **必须同时满足三条件**：工作流足够独立、会反复发生、无法并入任何现有剧本 | 剧本放 `.agents/skills/ccs-mode/playbooks/<英文短横线>.md` 并更新 `ccs-mode/SKILL.md` 分派表；独立技能放 `.agents/skills/<技能名>/SKILL.md` |

   - **完成标准**：每条候选都有唯一落点与排除其他层的原因；未同时满足第 6 级全部三条件时，不新建剧本或技能。

3. **按规范落地改动**
   - 纯分析或未要求改文件时只输出方案不落盘；涉及新建剧本、改工具规则或大改剧本前，先简述改动方案等用户确认。
   - 写或改剧本时遵守 [ccs-mode](../ccs-mode/SKILL.md)「B. 提炼剧本」写法规范：
     - 控制在一页以内，只写步骤、指向具体命令或入口（如 `pnpm -s ctl ...`、`references/features/`）与每步的完成标准，不写空泛口号；
     - 把用户纠正过的盲区写成明确核查步骤，最后一步必须是给出证据；
     - 补全占位剧本时保留该剧本的核心步骤基线（见 `ccs-mode/SKILL.md`「B. 提炼剧本」）；
     - 新建剧本时**必须同步更新** `.agents/skills/ccs-mode/SKILL.md` 的「判断类型」分派表；新建独立技能时遵守 `.agents/skills/<技能名>/SKILL.md` 命名、精简 YAML frontmatter（`name` + `description`），并确认 `.claude/skills` 符号链接可见（仓库当前无自动化校验 `.agents/skills/` frontmatter 或分派表的脚本，需人工核对）；同步清理重复或过时的旧表述。
   - **完成标准**：改动精准，新建剧本/技能均已挂进分派或发现入口，无冗余或冲突条款。

4. **跑项目检查与全新会话回归验证**
   - **静态检查**：仅改文档、剧本或技能时跑 `pnpm -s ctl check changed --files <改动文件>`（触及功能地图加跑 `pnpm -s ctl check features`）；改了工具或规则时补测试并按 [verify](../verify/SKILL.md) 跑 `ctl check changed` / `check all` 与 `ctl check rules`。
   - **全新会话回归**：每次补充、大改或新建剧本（或修改 `ccs-mode` 分派入口）后，按 `ccs-mode`「C. 检验剧本」设计一个同类最小真实任务，在**全新会话**中验证两件事：① 能否准确**选中**目标剧本或技能；② 能否按新步骤**自然用上新做法**并交付完整证据。当前会话无法代开用户主对话时，交付可直接执行的回归提示词并把真实新会话实测标为「仍待验证」。
   - **收尾提醒**：写完或大改剧本后提醒用户审阅并决定是否提交 git。
   - **完成标准**：项目检查全部输出 `"ok": true`；同类小任务回归已实际跑通，或已明确列出待在新会话执行的回归任务。

## 输出清单

1. **候选经验与证据表**：每条写明适用情形、具体做法、有效原因、原始证据，以及需要转交 `ccs-retro` 的反复失败项。
2. **落点决策**：选定的工具/规则/文档/剧本位置、排除其他优先级的原因，以及是否触发新建或更新分派入口。
3. **改动摘要**：修改或新增的文件路径、分派表或文档联动更新说明。
4. **验证结果与待验项**：已跑项目检查结果与输出；为本轮改动设计的同类小回归任务及新会话验证状态。
