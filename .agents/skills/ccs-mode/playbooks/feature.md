# 新功能 / 改功能

用途：新增或改变功能的行为、界面或命令，确认不破坏已有功能，并留下可复查的运行证据。

## 步骤与完成标准

1. **定规模、查地图与核实前提**
   - 用 `references/features/README.md` 定位相关功能页；**小改动**（单层、≤ 3 个业务文件、不改契约/存储）只读直接相关代码，不铺开读全套 `design/` 文档；**标准 / 跨层改动**沿 `contracts → Preload → Main → Utility → Renderer/i18n` 查清链路。
   - 涉及第三方服务或外部能力时先查官方文档核实协议与前提；外部网络探测必须加短超时（如 `curl --max-time 5`）。
   - **完成标准**：明确要改的文件范围、已有可复用机制及外部事实前提。

2. **复述方案并对齐关键分叉**
   - 说明要做什么、不做什么、改动文件、关键取舍（附推荐项）及验收标准。
   - **完成标准**：用户确认方案后再改代码；即便改动对象明确，遇到可见交互或空态/异常分叉（单行省略 vs 换行、悬停 vs 常驻、失败隐藏 vs 回退兜底）也先用一句话对齐。

3. **按规范实现，先格式化再跑精准单测**
   - 守住 `AGENTS.md` 边界与 `rules/README.md`（不重复造轮子、不双重强转、不绕过 lint；测试用产品常量与 `*.example.test`）。新增控件/重做布局时先读 `DESIGN.md` 与 `design/` 对应控件规范，精简新增文案防超语言包体积预算。
   - 改完先执行 `pnpm exec prettier --write <改动文件>`，再从仓库根目录跑精准测试 `pnpm exec vitest run <仓库相对测试路径>`（不要进子包跑相对路径）。
   - **完成标准**：覆盖正常、边界与错误路径的单测及格式校验全部通过。

4. **隔离测试实例实测（按改动大小取证）**
   - 运行 `pnpm -s ctl env doctor`（未运行则 `env start`，`env.not_seeded` 先 `env seed`；异常先 `ui reload`），尽量用 `&&` 串联连续 `ctl ui` 操作。
   - **小改动 / 局部样式**：跑核心交互与 DOM/状态核对，在 `test/<日期-主题>/` 存 **2–3 张关键截图**（改前 / 改后 / 关键交互态）。**标准改动 / 新增页面**：按功能页走完整用户路径 + 相邻回归 + `ui audit` / `ui same` + `logs errors`（智能体/工具改动用 `agent run` / `agent trace`）。验证后恢复被改动的测试配置。
   - **完成标准**：实测成功、关键截图落盘、无新增错误；受阻项（缺真实凭据或 `DEEPWRITE_ELECTRON_SANDBOX`）如实标注。

5. **按需同步功能地图**
   - 仅当修改了功能入口、组件路径、关键行为、IPC 命令、CLI 参数或工具名时，更新 `references/features/` 对应页并跑 `pnpm -s ctl check features`。
   - **完成标准**：`check features` 输出 `"ok": true`（未涉及则跳过）。

6. **跑统一检查**
   - 工作区混有其他任务未提交改动时运行 `pnpm -s ctl check changed --files <本次改动文件>`；干净工作区运行 `pnpm -s ctl check changed`；触及 `packages/contracts/`、根配置、依赖或检查脚本时再跑一次 `pnpm -s ctl check all`。未再改代码时不重复跑同类测试。
   - **完成标准**：对应检查输出 `"ok": true`（禁止用 `eslint-disable`、`@ts-ignore` 或 `--skip` 绕过）。

7. **给出证据**
   - 回复列出：① 跑过的检查命令、结果与耗时；② 验证 CLI 实际执行的命令与关键输出；③ `test/<日期-主题>/` 下的代表性截图；④ 未完成或未验证项。
   - **完成标准**：回复自带完整验收证据，不遗漏未验证项。
