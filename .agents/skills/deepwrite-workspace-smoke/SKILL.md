# DeepWrite 创作空间冒烟验收

在仓库根目录工作。按 [TEST.md](../../../TEST.md#开发环境复用或重启) 确认 `pnpm dev` 实例和开发端点，按 [deepwrite-dev](../deepwrite-dev/SKILL.md) 使用 MCP。核对 `.codex/config.toml` 中 `deepwrite-dev` 的 Electron、桥接脚本与当前检出。已有同一路径且能连接时，复用连接。

1. 让窗口处于应用工作区。调用 `get_app_status` 确认 `rendererReady`，调用 `list_works` 确认目录可读。运行会切换当前作品，并使用开发版配置的模型。
2. 对每个待测类型调用 `manage_work(action: "create")`，标题用「创作空间验收 <批次号> <类型>」。短篇、剧本和长篇可选「科幻」，剧本杀可选「硬核推理」，学术可用 `empirical_paper`。记录本批次创建的 ID，所有写入和结构操作限制在这些合成作品。
3. 用 `get_work` 取得本轮实际文档 ID。选择下表的来源文档，模板有差异时用职责相同的文档。用 `read_document` 返回的 `revision` 作为 `baseRevision`，用 `write_document` 放入一到两句合成材料和本批次唯一的校验词。先回读目标，记录初始内容与版本。
4. 按 [工具用例](references/tool-cases.md) 核对本轮工具清单。按组执行真实调用，每个工具和有代表性的操作都要有状态与证据。用户指定子集时按该范围跑，并在报告中标清范围。
5. 用 `run_agent(mode: "normal", newConversation: true)` 发起各类型写作任务，保存 `workId`、`runId` 和 `sessionId`。提示智能体先用工具读来源和目标，再写入指定文档，每份末尾另起一行原样写校验词。每次只处理该作品的少量文档。保留已存在的文字和共享剧情结构。

| 类型 | 合成材料与来源 | 要求的产物 |
| --- | --- | --- |
| 短篇 | 剧情设计。修表匠在车站捡到明天的车票，决定寻找失主。 | 第一节正文一小段，另写该节人物选择和未解问题。 |
| 剧本 | 剧情设计。管理员在空剧院听见报幕，在道具箱找到信封。 | 第一集一场戏，含场景行、可拍动作和对白。另写本集已知和未知状态。 |
| 长篇 | 全书主线。潮汐钟提前三响，守钟人发现页码逆序，决定查换班签名。 | 查看目录，写第一章章卡和正文，保留原章并创建一章「换班签名」。 |
| 剧本杀 | 故事真相。馆员 19:05 把蓝印章放入修复箱，借用单有 19:10 的签名。 | 第一轮写玩家可见线索，保留签名时间且不泄露印章去向。确认保存后，用 `search` 的 `player_visible` 范围核对签名时间，再读写主持手册的揭晓条件及 19:05。两次写入依次提交。 |
| 学术 | 研究立意。合成研究问题是段落间距是否影响阅读完成时间。 | 在方法节写指引与正文，包含配对比较、秒数和顺序平衡。数据用 `[待补数据: 配对阅读时间]`，不虚构文献、参与者或结果。 |

## 核验

- 用 `get_agent_run` 逐个跟到终态，检查实际模式与 `toolUsage.byTool`。MCP 调用依据工具返回记账，内置工具依据轨迹计数记账。回读确认副作用。记录失败、归一化次数和复测结果。按 [deepwrite-dev](../deepwrite-dev/SKILL.md#running-deepwrites-agent) 处理等待、用户输入和会话恢复。发生连续相同工具失败时，停止本轮并回读已落盘内容，沿用 `sessionId` 只补剩余目标。
- 对每个目标重新调用 `read_document`，核对版本或内容确已变化、产物满足任务、末行匹配校验词。用 `search_text` 确认命中落在目标文档，来源命中只算原始材料。用 `get_work` 确认应有的目录变化。对剧本杀分别核对玩家和主持人可见的信息。
- 剧本杀 `open_in_app` 成功而 `run_agent` 返回 `external.not_ready` 时，先检查 DeepWrite 是否停在设置页。返回应用并确认作品工作区可见后再试一次。仍失败就记录错误和复现条件，继续其他类型。

## HTML 结果

按 [TEST.md](../../../TEST.md#报告规范) 归档 Markdown 摘要与报告索引。把自包含的 HTML 放在同名产物目录的 `index.html`。使用合成数据，避免外链资源。

- 首屏放作品通过数、MCP 工具覆盖数、内置调用成功与失败次数。显示批次、运行模式与模型，模型信息缺失时注明。
- 按五类作品列终态、产物和回读结果。再给 MCP 和内置智能体各一份逐工具明细，用文字标出通过、复测通过、失败、未测或因前置条件未完成。对子操作附证据。预期拒绝算失败路径通过，保留真实失败和复测记录。
- 写清统计口径。一次工具调用只算一次。只收到运行 ID、只看到模型自述或仅覆盖同名工具的另一种作品时，对应项目仍未验。保留合成作品供核对。
- 在 T3 中先用 `html_preview` 检查桌面和窄屏，再将预览高度传给 `html_render`，直接在对话里展示；同时提供 HTML 文件链接。使用流式布局与主题变量，详情可折叠，页面外层保持透明。
