# 长篇合并归档与账本确认验证

## 目标与成功标准

- 合并归档后，章节、伏笔触点、叙事落点和账本共享同一提交 ID。重试复用原记录，版本冲突时整批保持原状。
- 智能体能识别来自归档提案的文本，并通过最新账本查询确认该批次的保存结果。

## 环境

- macOS、Node 24.19.0、Electron 42.5.0。各测试使用合成长篇和独立临时目录。
- 构建输出到临时目录。冒烟使用独立 Electron 配置目录和编译后的 Core Utility。

## 步骤与命令

- L1 用 `pnpm exec vitest run <相关文件>` 验证长篇存储、索引契约、审批、智能体工具及中英文运行规则，共 15 个文件。工具用例经过 Pi 参数校验。
- L1 对改动文件运行 `pnpm exec prettier --check` 和 `pnpm exec eslint --max-warnings=0`。
- L2 运行 `pnpm typecheck`、`pnpm lint:boundary` 和隔离的 `electron-vite build --outDir <临时目录>`，并检查 Renderer 构建产物和体积预算。
- L2 通过实际 Core Utility 调用 `long.commitChapter`，重复提交同一提案，再读回工作区索引和连续性文件。

## 结果

- 修复前复现账本校验失败和连续性查询读到旧状态。
- 修复后 110 项定向测试通过。覆盖单章伏笔、多章合并及分步归档、无伏笔、旧账本、复核、正文与连续性文件版本冲突，以及自动和手动审批失败后原提案重试。
- 类型、格式、ESLint、进程边界与隔离构建通过。编译后 Core 冒烟输出 `DEEPWRITE_ARCHIVE_SMOKE_OK`，两次提交返回同一笔账本。
