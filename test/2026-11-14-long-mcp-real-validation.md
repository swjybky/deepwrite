# 长篇 MCP 优化后真实模型补测

## 目标与成功标准

- 验证旧账本复核、正文变更标记、真实重启与原会话续接、实际成员委派、无章卡先询问，以及 trace 统计准确性。
- 使用前轮三个 MCP 测试作品，正文不新增章卡强校验。

## 环境

- macOS，开发版 1.8.4，deepwrite-dev MCP，应用内已配置的真实模型，自动审批。
- 核对并重启开发版加载新代码；正常模式与团队模式；主动强制结束一次本轮启动的开发进程。

## 步骤与命令（L2，真实模型）

- 悬疑书：旧账本 unverified → 完整读取依据 → review_commit_id 复核 → Core 回读 current。
- 仅改第二章一处环境措辞 → Core 返回 needs_review，changedChapterIds 只含第二章。
- 复核过程中结束 Electron；重启后查询原 runId，恢复 interrupted、原 sessionId 与最后完成工具；另一个已完成 runId 恢复 completed。
- 以原 sessionId 续做未完成复核；落盘后回读 current，同一账本标识、记录数仍为一。
- 科幻书团队模式实际调用 spawn_subagent，成员写入第三章正文；MCP 回读 757 字符，第三章未新增账本。
- 世情书无第四章章卡时先 ask_user_question；记录显示用户选择先拟章卡，随后仅生成第四章章卡，正文保持空白。

## 结果

- 五轮运行（含中断轮）合计 60 次内部工具调用：成功 56、失败 4，成功率 93.33%；按持久化主/成员 trace 去重，与 MCP toolUsage 相符。
- 4 次参数失败：list 对 book_line 使用 continuity；章节 handoff 多传 chapter_id；成员两次传 max_chars 却不传 range。均在后续调用中恢复。
- 账本与断点续接链路最终走通，未重复建账；恢复查询不自动重发消息。正文测试措辞保留，账本已复核至该版本。
- 真实重启刚就绪时两次 get_agent_run 返回“窗口无法打开目标”；目录加载完成后原请求成功。外层启动时序失败单列，不混入内部工具成功率。
- 模型首次把提案落盘前的旧状态误解释为预期；实际 Core 回读证明已 current，因此不能采用模型自述作为保存证据。

## 未覆盖与后续

- 启动就绪与目标目录加载的时序仍需修复；成员额外读取人物档案，尚未达到章卡＋前章结尾的最简取材目标。
- 尚未实际覆盖切换世界观/人物焦点后的追问、触发剪枝后的全文重读，以及手机编辑后的账本状态更新。
