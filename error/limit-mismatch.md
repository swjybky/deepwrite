# 同一数据的上限不一致

返回 [ERROR.md](../ERROR.md)。

**症状：**`too_big`、`maximum 64` 等校验错误；写入成功但读取、恢复或另一层写入失败；子智能体内容里没有该字段却反复报错。

**根因：**同一份数据在写入、读取、事务恢复或不同模块各设上限（例：名册别名 100 条，长篇人物别名 64 条，原样拷贝即失败）。

**处理：**

- 上限定义在 contracts 一处并导出，写入、读取、恢复共用（参考 `job-state-store.ts`、`completion-ledger.ts`）。
- 跨模块转换时用导出的整理函数截断或去重（如 `fitLongCharacterAliases`），不调大下游上限——手机端与旧版本会读不了。
- 系统侧整理导致的失败报“系统侧保存失败，不要重交”，不让模型盲目重试。

**预防：**为上限边界写测试（恰好等于、超出一条），并覆盖“上游上限 > 下游上限”的转换路径。
