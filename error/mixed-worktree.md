# 工作区混有他人改动

返回 [ERROR.md](../ERROR.md)。

**症状：**`typecheck` / `test` 报与本次改动无关的错；`git status` 有大量非本次文件；同一文件里有别人的片段。

**根因：**多个会话共用同一工作区，其他会话的未完成工作留在其中。

**处理：**

- 用 `git diff` 与自己的改动清单区分归属；不回滚、不格式化、不“顺手修”他人改动。
- 验证报告写明哪些失败属于他人改动，以及本次改动相关的检查是否通过。
- 提交时按文件或按块暂存，只含本次改动（见 `git-commit` skill）。

**预防：**开工前记录 `git status` 基线；改动范围大时建议用独立 worktree。
